  184 total" because 2 are skipped entirely.
- **Naming convention:** `*.test.{js,ts,tsx}` for Jest, `*.spec.ts` for Playwright. The split
  is load-bearing — `jest.config.cjs` excludes `/e2e/` by path because Playwright specs import
  `@playwright/test`, "which is not jest-compatible".
- **Setup files and where they run:**
  - `jest.setup.ts` (root, `setupFilesAfterEnv`) — imports `@testing-library/jest-dom`, then
    polyfills what jsdom lacks: `TextEncoder`/`TextDecoder` from `node:util`,
    `ReadableStream`/`WritableStream`/`TransformStream` from `node:stream/web`, a mock
    `IntersectionObserver` (Framer Motion `whileInView`), `__DEV__ = true` (mobile `App.tsx`
    reads it at import time) and a `performance.now` fallback.
  - `apps/mobile/jest.setup.cjs` (mobile config only) — silences the
    `Animated: useNativeDriver` warning, and `jest.mock`s `Linking` (modern and legacy
    specifiers, `{virtual: true}`), `Share` and `Appearance`.
  - `@testing-library/react-native/extend-expect` is also in the mobile setup files.

### 4) Mocking and Isolation Strategy

- **Main mocking approach: `moduleNameMapper`, not `jest.mock`.** The root config maps whole
  modules to **14 hand-written mocks in `__tests__/__mocks__/`** — `react-native`,
  `expo-status-bar`, `expo-modules` (haptics/system-ui), `expo-location`,
  `expo-notifications`, `react-native-gesture-handler`, `-safe-area-context`, `-screens`,
  `-reanimated`, `-svg` (also serving `@shopify/flash-list`), `react-navigation` (all three
  packages), `async-storage`, `netinfo`, `tanstack-react-query`, plus `empty-string.js` for
  `\\.md$` assets. The config comments state why: *"Node/jsdom test environments cannot parse
  react-native's Flow-typed sources."* `jest.mock` is used only inside the mobile config's
  setup file (`Linking`, `Share`, `Appearance`, all `{virtual: true}`).
- **Transform-everything policy.** `transformIgnorePatterns: []` — with the reasoning in-file:
  *"Small dependency set, many ESM-only packages (react-markdown's unified/remark ecosystem):
  transform everything instead of maintaining a per-package exception list that breaks on
  every new ESM dependency."* `babel.config.cjs` adds `babel-plugin-transform-import-meta`
  because preset-env transpiles to CJS where `import.meta` is a SyntaxError, and forces
  `sourceType: 'module'` for `backend/**/*.js`.
- **Injectable seams instead of global mocks** where an integration matters:
  `fetchAdvisoryFile(config, { fetchImpl = globalThis.fetch })`
  (`backend/services/kaggleAdvisoryClient.js`); Telegram/SMS take an `env` argument
  (`readTelegramConfig(env)`); the forecast store has `resetForecastStore()` and
  `FORECAST_STORE_MEMORY=true`; Open-Meteo exports `clearCache()`.
- **Isolation guarantees:**
  - `maxWorkers: '50%'` — *"the API suites import the full Express app (heavy babel transforms
    of ESM deps), and unbounded workers OOM small CI runners."*
  - Explicit reset hooks per singleton: `resetForecastStore()`, `clearCache()`,
    `resetKaggleCache()`; `ai_fallback_engine.js` exposes breaker state for inspection.
  - `moduleDirectories: ['node_modules', 'frontend/node_modules']` at the root; the mobile
    config deliberately uses **plain upward resolution** (global module paths *"shadowed Jest
    29's nested `pretty-format` with React Native's v26 copy"*).
  - The mobile config pins `react` and `react-test-renderer` to Expo's React **18.2** while
    the web workspace runs React **18.3.1** — *"relying on workspace hoisting causes invalid
    hooks."*
  - The dispatcher mutates the request in place when stripping routing artefacts, so **a test
    harness that reuses one request object across invocations must rebuild it per call**
    (`serverless/dispatch.js`).
  - **Isolation *against the committed data* is the current gap** (§5, class B): several
    suites assumed a stale/absent fallback snapshot and now fail against fresh committed data.
- **Common failure modes in these tests — documented in-repo:**
  1. **cwd-relative Babel resolution** (from the 2026-10-02 audit): `configFile` paths in
     `apps/mobile/jest.config.cjs` must resolve against `__dirname`, not the cwd.
  2. **Open handles after the RN run.** Reproduced at HEAD: the run needs `--forceExit`;
     Jest prints the *"did not exit one second after the test run"* notice. Owner Action 13
     tracks removing the flag.
  3. **Conditional skips that look like coverage.** Suites gate themselves on a built
     `frontend/dist` (`__tests__/seoFoundations.test.js`, `statusPagePrerender.test.js`,
     `structuredData.test.js`). Without a build they skip silently — 2 suites skip in this
     sandbox's no-build run. That is exactly why `ci.yml`'s `verify` job (the only job that
     builds) re-runs those explicitly in a *"Post-build surface checks"* step.

## Extended Sections (Optional)

### Framework-specific suite patterns worth copying

- **Ledger + ratchet.** A gate is a Jest suite **plus** a frozen JSON baseline in
  `data/design/` carrying a `why` block that names the audit finding it came from. The
  assertion is always `toBeLessThanOrEqual(BASELINE)`. `data/design/svg-paint-baseline.json`
  states the rule outright: *"Counts may only go down."*
- **Build-conditional suites that announce themselves.** `if (!built) { … }` prints why the
  suite is skipping rather than skipping silently.
- **Config-shape tests as deployment guards.** `__tests__/modelArtifactsNotServed.test.js`
  asserts that no rewrite, redirect or hosting root points at `Models/` — *"the deployment
  configs were only protected by convention: nothing failed if a rewrite … started pointing
  at the artifacts."* (At HEAD the binaries themselves are deleted; the guard still passes.)
- **Pure decision functions extracted for testability.**
  `rateLimitDecision(entry, {limit, windowMs}, now = Date.now())` — *"Pure decision function,
  so the window arithmetic is testable without an HTTP server"*
  (`backend/middleware/serverlessGuard.js`).
- **Exit codes as a tested contract.** `scripts/fetch_kaggle_advisory.mjs` uses
  `0 fresh / 2 unchanged-or-stale / 1 failed`, the workflow branches on it, and the workflow's
  own comment forbids `set -e` on that step so the branch can read the code.
  ~~`scripts/tests/test_workflows.py`~~ used to parse the workflows with PyYAML to assert
  their shape — **deleted at HEAD**, so CI configuration is no longer under test.

### Test performance notes

- The full root run costs ~2.2 min with coverage in this sandbox; CI splits coverage across
  the backend and frontend jobs instead of collecting it once.
- `maxWorkers: '50%'` is an OOM guard, not a speed choice; the API suites are the heavy ones
  because they import the full Express app and drag the ESM dependency graph through Babel.
- `transformIgnorePatterns: []` means **every** `node_modules` file imported by a suite is
  transpiled — the deliberate trade for never maintaining an ESM exception list.
- The mobile run is fast (25.3 s) but does not exit — the `--forceExit` in CI is what keeps
  the job from hanging, and it is the flag Action 13 wants removed.
