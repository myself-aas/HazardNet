## Core Sections (Required)

### 1) Test Stack and Commands

- Primary test framework: **Jest 29** (`jest` ^29.7.0, `ts-jest` ^29.4.12, `babel-jest` ^30.4.1, `jest-environment-jsdom` ^30.4.1) configured at the **repo root** (`jest.config.cjs`) — one Jest project covers both the JS backend suites and the TS/TSX frontend suites.
- Assertion/mocking tools: Jest `expect`; **@testing-library/react 14** + **@testing-library/jest-dom 6** (loaded globally via `jest.setup.ts`); **node-mocks-http** and **supertest** for backend route/middleware tests; Playwright's own `expect` for e2e.
- Commands:

```bash
npm test                       # jest --passWithNoTests (all unit/integration suites)
npx jest --ci                  # what CI runs (.github/workflows/ci.yml)
npx jest __tests__/security.test.js   # single suite (standard jest CLI)
npm run lint                   # tsc --noEmit (type-level test of the frontend)
npx playwright install chromium && npx playwright test   # e2e smoke suite (built app on :4173, or E2E_BASE_URL)
npm run check:rag-freshness    # data-freshness gate (quasi-test, CI-enforced)
npm run check:bundle           # bundle-budget gate (CI-enforced)
```

Coverage run: Jest `--coverage` is configured (thresholds + `collectCoverageFrom`), but no package script wires it; CI does not currently publish coverage `[TODO]`.

### 2) Test Layout

- Test file placement pattern: **co-located `__tests__/` directories** next to the code under test.
  - Root `__tests__/` — 13 backend/serverless suites: `conversions`, `ingest`, `normalization`, `predict`, `predictionCache`, `push`, `security`, `supabaseAuth`, `forecastRow` (CSV row parser), `forecastsUpdate` (supertest multipart integration of `POST /api/v1/forecasts/update` with mocked Firestore), `forecastStore` (ADR 0002 store: mode selection + fail-loud config, Firestore latest-per-district/batch-replace, Supabase DISTINCT-ON query, delete+insert transaction with rollback, upsert append, pg→API row-shape parity, `getLatestPredictionDate` probes; self-contained `jest.mock` factories with `jest.requireActual('pg')` spread for the type-parser side effects), `forecastFreshness` (gauge wiring against the real prom-client registry exposition: set-on-data, absent-on-empty/error, 60s probe cache, age recomputed per call), `metricsApi` (Vercel `/api/metrics`: 405, gauge exposition with data, absent without, 503 on store failure), `forecastsHistory` (`GET /api/v1/forecasts/history`: window validation incl. format/ordering/90-day cap, default 30-day window, filter pass-through, JSON shape, archive-format CSV export with escaping + attachment headers) (1,000+ lines total). Full run 2026-09-12: **34 suites / 313 tests green** (horizon fixtures migrated to 10/20/30 + ADM3 identity columns, ADR 0005; + ADM3→ADM2 rollup suite — dominant hazard, mean confidence, alias matching, legacy passthrough — ADR 0006 8d).
  - `frontend/src/**/__tests__/` — 19 suites across `components/` (AdvisoryPanel, RegionSelector, auth BrandPanel/AuthSocialButtons, blog blogGuard, blog/ads BlogAdUnit, map DistrictForecastCard), `lib/` (avatar, blogArticles, blogSeo, connectors, downloadChannels, forecasts, oauthProviders, passwordStrength, seoHead, username), `pages/` (AuthPages, Blogs.studioButton), `utils/` (pdfPagination).
- Naming convention: `<Subject>.test.ts(x)` (frontend), `<area>.test.js` (root/backend); e2e uses `<name>.spec.ts` in `e2e/`.
- Setup files and where they run: `jest.setup.ts` (`setupFilesAfterEnv` → `import '@testing-library/jest-dom'`); Babel handles TS/TSX + ESM via `babel.config.cjs` (`@babel/preset-typescript`, `preset-react`, `preset-env`); `transformIgnorePatterns: []` so ESM-only packages (@supabase, react-markdown's unified/remark ecosystem) get transformed (config comment).

### 4) Mocking and Isolation Strategy

- Main mocking approach: **module/function level** — `node-mocks-http` request/response objects for middleware; mocked Firestore calls in route tests; Testing Library renders components with mocked context/props; the Proxy-based mock Supabase client (`frontend/src/lib/supabase.ts`) doubles as both a production fallback and a test convenience. No MSW / network-layer mocking; no Jest module-registry isolation harness.
- Isolation guarantees: each suite imports fresh modules; in-memory caches (prediction/advisory) are tested directly. Playwright runs `fullyParallel` with per-worker contexts against a built app (`npm run build && npx vite preview --port 4173`).
- Common failure mode in tests: ESM/CJS friction — the config comments document the exact historical failures (Jest picking up Playwright specs → `testPathIgnorePatterns: ['/e2e/']`; ESM-only deps needing full transform; `bun.lock` v1 vs Vercel). When adding dependencies, expect `transformIgnorePatterns` and lockfile-version interactions.

### 5) Coverage and Quality Signals

- Coverage tool + threshold: Jest coverage with a **global gate** — statements **32**, branches **35**, functions **30**, lines **31** (`jest.config.cjs`); explicitly a "ratchet upward" floor set at the 2026-08-28 measured baseline (QA-01).
- Scope of the gate: `collectCoverageFrom: backend/**/*.js, api/**/*.js, frontend/src/utils/**/*.ts` — i.e. the gate measures backend + serverless + frontend utils only, **not** the React component tree.
