## Core Sections (Required)

### 1) Test Stack and Commands

- **Primary test framework:** Jest **29** (`jest@^29.7.0`), driven through `babel-jest`
  (`babel.config.cjs`: preset-env → node current, preset-typescript, preset-react automatic, plus
  `babel-plugin-transform-import-meta` so ESM backend modules load under the CJS transform).
  `ts-jest` is installed but the root config transforms everything with Babel.
- **Assertion/mocking tools:** Jest `expect` + `@testing-library/jest-dom`,
  `@testing-library/react` (web), `@testing-library/react-native` (mobile), `jest-axe`
  (accessibility), `supertest` + `node-mocks-http` (HTTP surfaces), `jest.mock()` and
  hand-written module stubs.
- **Other runners:** Playwright **1.62** (`playwright.config.ts`, plus a QA-only
  `playwright.qa.config.ts`), Maestro (`apps/mobile/.maestro/*.yaml`, not wired into CI),
  **pytest** for the pipeline/workflow suites, and `node --test` for the four phase suites
  (`npm run test:phases`).

```bash
# Everything (root Jest: backend + api + packages + root suites)
npm test                                   # jest --passWithNoTests (no coverage gate)

# Backend scope — exactly what CI runs (.github/workflows/ci.yml, job test-backend)
npx jest --ci --coverage --coverageDirectory=./coverage/backend \
  --testPathIgnorePatterns='/node_modules/' '/e2e/' '/frontend/' '/apps/' '/__mocks__/'

# Frontend scope — what CI runs (job test-frontend), run from frontend/
cd frontend && npx jest --ci --config ../jest.config.cjs --rootDir .. \
  --coverage --coverageDirectory=./frontend/coverage --coverageThreshold='{}' frontend/src

# Mobile (React Native / Expo) — MUST be run from apps/mobile (see §5)
cd apps/mobile && npx jest --config jest.config.cjs

# Pipeline + workflow-shape tests (Python)
python -m pytest scripts/tests -q

# Phase suites (node:test)
npm run test:phases

# Post-build surface checks (require frontend/dist; run in the `verify` job)
npx jest --ci --config jest.config.cjs --rootDir . \
  __tests__/seoFoundations.test.js __tests__/statusPagePrerender.test.js __tests__/structuredData.test.js

# E2E (needs a production build + a server)
npm run build
npm --prefix frontend run preview -- --host 0.0.0.0 --port 3000 &
npx playwright test                        # E2E_BASE_URL / QA_NO_API_RUNTIME set in CI

# Mobile E2E (Maestro, local only)
cd apps/mobile && npm run test:maestro
```

### 2) Test Layout

- **Root suites** `__tests__/`: 60 top-level `*.test.js` files plus `alerts/` (9), `api/` (7),
  `mobile/` (3) and `__mocks__/` (14 hand-written stubs for React Native/Expo/native modules).
  These cover the API surface, the alert engine, artifact builders, security/design/token parity
  and the "phase" gates.
- **Co-located frontend tests** `frontend/src/**/__tests__/*.test.ts(x)` (58 files:
  `components/`, `pages/`, `hooks/`, `lib/`, `services/`, `utils/`).
- **Package tests** `packages/{core,api}/__tests__/*.test.ts` (9 + 1 files).
- **Mobile component tests** `apps/mobile/__tests__/*.test.tsx|js` (9 files).
- **E2E** `e2e/*.spec.ts` (6 specs + `helpers.ts`), all discovered by the default `testMatch` in
  `playwright.config.ts` (the file's header states that a spec must never be silently excluded
  from the regex).
- **Python pipeline tests** `scripts/tests/test_*.py` (9 files) + `scripts/tests/fixtures/`.
- **Setup files:** `jest.setup.ts` (root) mounts `jest-dom`, polyfills `TextEncoder/Decoder`,
  web streams and `IntersectionObserver` for jsdom, and defines `__DEV__`;
  `apps/mobile/jest.setup.cjs` mocks `Linking`, `Share`, `Appearance`, keyboard/insets and silences
  the `useNativeDriver` warning.

### 4) Mocking and Isolation Strategy

- **Main mocking approach:** module-level stubbing. React Native and Expo native modules are
  unmockable in jsdom, so `jest.config.cjs` `moduleNameMapper` maps 18 patterns (17 native/Expo/
  navigation module specifiers plus `\.md$`) to the
  hand-written stubs in `__tests__/__mocks__/` (`react-native`, `expo-*`, `@react-navigation/*`,
  `react-native-svg`, `@shopify/flash-list`, async-storage, netinfo, `*.md` → empty string).
- **HTTP:** `supertest` against the exported Express `app` (note: `backend/server.js` binds a port
  **only** when invoked directly, so parallel suites cannot collide) and `node-mocks-http`
  `req`/`res` objects for the Vercel handlers. No live network, no test database.
- **Firestore:** never contacted in tests — suites inject a store, call `resetForecastStore()` /
  `resetAlertStore()`, or assert on a `0`-record path; a real connection failure is what
  `__tests__/metricsApi.test.js` exercises (`connection refused` → gauge hidden).
- **Third-party APIs:** `jest.fn()` fetch injection — the Open-Meteo client, the Telegram and SMS
  transports take `fetch` (or an `env` object) as a parameter, and `TELEGRAM_API_BASE` /
  `BULKSMSBD_API_BASE` / `GREENWEB_API_BASE` exist so a test can point them at a stub.
- **Isolation guarantees:** `jest.setup.ts` runs per test file (jsdom globals are per-environment);
  `resetForecastStore()` / `resetAlertStore()` drop the module-level singletons between suites;
  `maxWorkers: '50%'` caps parallelism because the API suites import the whole Express app.
- **Common failure mode:** ESM-only dependency transforms. `transformIgnorePatterns: []`
  (transform everything) is deliberate, which makes the frontend run slow (~51 s for 58 suites)
  but avoids per-package exception lists.

**Known gaps / fragile areas**

- The 2 skipped suites (`seoFoundations`, `statusPagePrerender`) self-skip unless
  `frontend/dist/index.html` exists — they only execute in the `verify` job; `structuredData`
  partially skips for the same reason.
- Mobile suites are absent from every workflow, so the RN/Expo surface is effectively untested in CI.
- Maestro flows are not run in CI.
- The coverage gate is a ratchet that was never tightened after coverage roughly doubled.
- 23 skipped tests in the backend scope (mostly the two self-skipping suites).

### Mock recipes by dependency type

| Dependency | Recipe | Where |
|------------|--------|-------|
| React Native core & native modules | Map to `__tests__/__mocks__/*.js` stubs in `jest.config.cjs` | `__tests__/__mocks__/` |
| Expo modules (`expo-haptics`, `expo-status-bar`, `expo-system-ui`, `expo-location`) | Same stubs (`expo-modules.js`, `expo-location.js`) | `jest.config.cjs` |
| Markdown article assets | `\.md$` → `empty-string.js`; mobile uses `jest.fileTransform.cjs` | `jest.config.cjs`, `apps/mobile/jest.config.cjs` |
| Express app | `supertest(app)` — `backend/server.js` exports `app` and only binds a port when run as a script | `__tests__/api/*.test.js` |
| Vercel handlers | `node-mocks-http` `createRequest/createResponse` + `guardRequest()` bypass | `__tests__/api/serverlessRouting.test.js`, `__tests__/metricsApi.test.js` |
| Fetch/Open-Meteo/Telegram/SMS | Inject `fetch` or `env` into the client/transport; override `*_API_BASE` | `backend/utils/openMeteo.js`, `backend/alerts/channels/*.js` |
| Firestore | Injected store + `resetForecastStore()` / `resetAlertStore()`; never a live connection | `__tests__/forecastStore.test.js`, `__tests__/alerts/*.test.js` |
| Committed artifacts | Read real files from the working tree and assert properties (no mocks) | `__tests__/freshnessArtifact.test.js`, `__tests__/contentEngine.test.js`, `__tests__/brandAssets.test.js` |

### CI test topology

| Job | Command | Artifacts / gates |
|-----|---------|-------------------|
| `test-backend` | `npx jest --ci --coverage …` (backend scope) | Codecov upload, flag `backend`; coverage thresholds apply |
| `test-frontend` | `npx jest … frontend/src` with `--coverageThreshold='{}'` | Codecov upload, flag `frontend` |
| `test-pipeline-scripts` | `python -m pytest scripts/tests -q` + two snapshot-builder smoke tests | Guards the builders and every workflow YAML (no `secrets` in `if:`) |
| E2E job | `npx playwright test` against `vite preview` | Playwright HTML report (7-day retention) |
| `verify` | env validation, tsc, ESLint, model-version handshake, "serverless functions load as ESM", Vercel budget, claims registry, design gate, build, bundle budget, public-path check, derived-artifact checks, content-index check, post-build surface suites | Build artifact `frontend-dist` |
| `security-audit` | `scripts/check-secrets.sh`, `node scripts/npm-audit-ci.mjs` | Fails on expired exceptions in `audit-exceptions.json` |
