## Core Sections (Required)

### 1) Test Stack and Commands

- **Primary test framework**: Jest 29.7 (backend/API/frontend unit + integration) and Playwright 1.62 (browser E2E). Python: pytest 9.1.1.
- **Assertion/mocking tools**: `@testing-library/react` 14 + `@testing-library/jest-dom` 6 (DOM assertions), `jest-axe` 9 + `@types/jest-axe` (accessibility assertions), `supertest` 7 and `node-mocks-http` 1.11 (HTTP without a socket), `ts-jest` 29.4 as the declared preset with `babel-jest` 30 as the actual transform.

Commands:

```bash
npm test                                              # jest --passWithNoTests (root config)
npx jest --ci --coverage --coverageDirectory=./coverage/backend \
  --testPathIgnorePatterns='/node_modules/' '/e2e/' '/frontend/'   # CI: backend suites + coverage gate
cd frontend && npx jest --ci --config ../jest.config.cjs --rootDir .. \
  --coverage --coverageDirectory=./frontend/coverage --coverageThreshold='{}' frontend/src  # CI: frontend suites
npm run test:e2e                                      # Playwright (see note below)
npx playwright test                                   # equivalent direct invocation
python -m pytest scripts/tests -q                     # pipeline + workflow guard suites
cd scripts && python -m hindcast.cli check --require-reports   # hindcast reports recompute gate
```

> Note: `README.md` instructs contributors to run `npm run test:e2e`, but **no `test:e2e` script exists** in `package.json`. The real invocation is `npx playwright test`. See CONCERNS.

### 2) Test Layout

- **Test file placement pattern**: three conventions by runner.
  - Root `__tests__/` — **52** `.test.js` files covering backend utilities, `api/` handlers and cross-cutting contracts, with two sub-folders: `__tests__/alerts/` and `__tests__/api/`.
  - Co-located `__tests__/` under `frontend/src` — **33** files, concentrated in `frontend/src/lib/__tests__/` (17) with smaller groups for `components` (4), `pages` (4), `components/alerts` (2), `components/auth` (2), and one each for `components/blog`, `components/blog/ads`, `components/map`, `frontend/src/utils`.
  - `scripts/tests/` — **24** pytest modules (`test_*.py`) plus `test_csv_ingestion.mjs`, and a `fixtures/` directory.
  - `e2e/` — **3** Playwright specs (`smoke.spec.ts`, `critical-paths.spec.ts`, `mobile-responsive.spec.ts`) + `helpers.ts`.
  - `training/tests/` — 1 additional suite for the Bangladesh-threshold proofs.
- **Naming convention**: `<subject>.test.js|ts|tsx` (Jest), `<area>.spec.ts` (Playwright), `test_<subject>.py` (pytest).
- **Setup files and where they run**: `jest.setup.ts` is registered via `setupFilesAfterEnv: ['<rootDir>/jest.setup.ts']` in `jest.config.cjs`. It imports `@testing-library/jest-dom` and polyfills `TextEncoder`/`TextDecoder` from `node:util` because jsdom 30 does not expose them while jspdf's import chain requires them. `babel.config.cjs` (loaded by `babel-jest` for every transformed file) applies `babel-plugin-transform-import-meta` so `import.meta.url` in `rag_pipeline/*` survives CJS transpilation.

### 4) Mocking and Isolation Strategy

- **Main mocking approach**: module-level `jest.mock` plus purpose-built injection seams. Production modules expose explicit reset hooks for tests — `resetForecastStore()` ("Test/maintenance hook: drop the cached store", `backend/forecastStore.js`) and `resetAlertStore()` (`backend/alerts/store.js`) — and `backend/utils/openMeteo.js` exposes `clearCache()`.
- **Isolation guarantees**: `jest.config.cjs` sets `testEnvironment: 'jsdom'` globally (so backend suites also run in jsdom), `maxWorkers: '50%'` to bound memory ("unbounded workers OOM small CI runners"), and `testPathIgnorePatterns: ['/node_modules/', '/e2e/']` to keep Playwright specs out of Jest.
- **Transform strategy is deliberately permissive**: `transformIgnorePatterns: []` — the config comment explains this avoids "maintaining a per-package exception list that breaks on every new ESM dependency" for the react-markdown/unified/remark ecosystem.
- **Common failure mode in tests**: ESM/CJS interop. Both `babel.config.cjs` and `jest.config.cjs` carry long comments about past breakages here (`import.meta` in `rag_pipeline` cascading through `backend/server.js` "22 red tests"; ESM-only dependencies). This is the area most likely to break a suite after a dependency upgrade.
- **Offline fixtures for pipeline tests**: `scripts/tests/fixtures/` plus `make_fixture_csv.py` and `make_mlops_fixtures.py` generate deterministic inputs, so the Python suites need no network.

### 5) Coverage and Quality Signals

- **Coverage tool + threshold**: Jest's built-in `--coverage`, with a hard global gate in `jest.config.cjs`:
  `statements: 32`, `branches: 35`, `functions: 30`, `lines: 31`.
  Scope is bounded by `collectCoverageFrom`: `backend/**/*.js`, `api/**/*.js`, `frontend/src/utils/**/*.ts` — i.e. **frontend components/pages/hooks are excluded from the coverage denominator and from the gate**.
- **Threshold provenance and ratchet policy** (from the config comments): the floor is the measured 2026-08-28 baseline (~32% statements) minus a small margin, "ratchet upward as tests land". The CI frontend job disables the gate (`--coverageThreshold='{}'`) because a frontend-only run can never satisfy backend-calibrated thresholds; its stated baseline is ~17% statements (lib/utils only), to be gated once component tests land.
- **Current reported coverage**: `[TODO]` — not measured in this environment (no `node_modules`). Historical baselines are recorded in-project as ~32% statements (backend/API/utils, 2026-08-28) and ~17% statements (frontend lib/utils).
- **Coverage reporting**: uploaded per job to Codecov (`flags: backend` / `flags: frontend`) with `fail_ci_if_error: false`, so a Codecov outage cannot fail the build.
- **Other enforced quality signals** (all fail the build, not warn):
  - ESLint in CI is run as a **0-error policy** (`npm run lint:eslint`) even though individual rules are set to `warn` — i.e. only errors block.
  - Bundle budget: `npm run check:bundle`.
  - Claims registry: `node scripts/check-claims.mjs` — "every metric-shaped number in public copy must be registered in `docs/CLAIMS.md`… Fabricated or unregistered metrics fail the build."
  - Model claims: `scripts/tests/test_model_claims.py` fails when copy advertises a horizon the code cannot produce.
  - Secret scan: `bash scripts/check-secrets.sh`; dependency audit: `node scripts/npm-audit-ci.mjs` (fails closed on any high/critical advisory not listed in `audit-exceptions.json`, and fails on **expired** exceptions).
  - Model provenance: `node scripts/gen-model-version.mjs` + a `git status --porcelain -- Models/VERSION.json` check that detects a *missing* file as well as a stale one.
- **Known gaps / flaky areas**:
  - No E2E or unit coverage of live third-party providers; the AI cascade is untested against real 429/quota behaviour.
  - Post-build suites silently self-skip wherever `frontend/dist` is absent, so a local `npm test` gives a weaker signal than CI.
  - Frontend has no coverage gate.
  - Playwright previously needed a quarantine (`timeout: 30s`, `retries: 0`, `continue-on-error: true`); both the quarantine and the E2E quarantine in CI were removed after the root causes were fixed (a Leaflet/global-`L` Rolldown crash and a Vercel-only analytics script path). Recorded in `playwright.config.ts` and `.github/workflows/ci.yml`; regression evidence in `docs/audits/2026-09-13-e2e-green-and-codebase-audit.md`.
