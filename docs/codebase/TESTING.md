## Core Sections (Required)

### 1) Test Stack and Commands

- **Primary test framework:** **Jest 29.7.0** with `babel-jest` 30 as the transform
  (`jest.config.cjs`, `babel.config.cjs`). Default environment **jsdom**
  (`jest-environment-jsdom` 30).
- **Secondary runners:**
  - **Playwright 1.62** (`@playwright/test`) for E2E over a **built** app — two configs.
  - **`node --test`** for the phase gates (`npm run test:phases`) and for the advisory pipeline
    suite inside `daily_advisory_ingest.yml`.
  - **`pytest`** (declared `>=8,<9`; 9.1.1 installed here) for `scripts/tests/*.py`.
  - **Maestro** for four mobile device flows (`apps/mobile/.maestro/*.yaml`) — not run in CI.
- **Assertion / mocking tools:** Jest `expect`; `@testing-library/jest-dom` (registered in
  `jest.setup.ts`); `@testing-library/react` 14 for web components; `@testing-library/react-native`
  12 for RN components; `jest-axe` for accessibility assertions; `supertest` + `node-mocks-http`
  for HTTP-level API tests; `react-test-renderer` for the RN tree.
  **No `jest.mock`-heavy DI framework** — mocking is done through `moduleNameMapper` (§4).
- **Commands:**

```bash

npx jest --ci --silent

# the two CI subsets

  --testPathIgnorePatterns='/node_modules/' '/e2e/' '/frontend/' '/apps/' '/__mocks__/'

# React Native (must be run from the repo root; needs --forceExit — see §4)
npx jest --config apps/mobile/jest.config.cjs --ci --forceExit

# Python pipeline suite
python3 -m pytest scripts/tests -q

# phase gates and the advisory pipeline, via the Node runner
npm run test:phases
node --test __tests__/advisoryPipeline.test.js

# E2E (requires a build first)
npm run build && npx vite preview --port 4173 &   # or: E2E_BASE_URL=http://localhost:3000

npx playwright test -c playwright.qa.config.ts    # sandbox variant, needs QA_CHROMIUM_PATH
```

### 2) Test Layout

- **Placement is deliberately mixed, and one root Jest project collects almost all of it:**

  | Location | Suites | What lives there |
  |---|---|---|
  | `__tests__/` (root) | **97** | backend, API, pipeline, security, design-gate and phase-gate suites; subdivided into `__tests__/alerts/` (8), `__tests__/api/` (7), `__tests__/mobile/` (3); plus `__tests__/__mocks__/` (14 hand-written module mocks) |
  | `frontend/src/**/__tests__/` | **76** | co-located: `lib/__tests__/` (33), `pages/__tests__/` (12), `components/__tests__/` (10), `hooks/__tests__/`, `services/__tests__/`, `styles/__tests__/`, `utils/__tests__/` |
  | `packages/core/__tests__/` | **9** | one per core module (alertPolicy, dataStates, dedupe, freshness, geo, haptics, notifications, queryKeys, savedPlaces) |
  | `packages/api/__tests__/`, `packages/analytics/src/__tests__/` | **1 + 1** | client contract; streaming tracker |
  | `apps/mobile/__tests__/` | **12** (separate config) | RN component suites under `@testing-library/react-native` |
  | `scripts/tests/` | **8 `.py` + 1 `.mjs`** | pipeline validators, content engine, workflows, secret scan, security disclosure, blog authz parity, status surface, frontend alert surface; fixtures in `scripts/tests/fixtures/` |
  | `e2e/` | **6 specs + `helpers.ts`** | `smoke`, `critical-paths`, `mobile-responsive`, `forecast-ux`, `navigation-a11y`, `full-app-qa` (626 lines) |

  Total for the root project: **184 suites** (97 + 76 + 9 + 1 + 1). Verified with
  `npx jest --listTests | wc -l`.
- **Naming convention:** `*.test.{js,ts,tsx}` for Jest, `*.spec.ts` for Playwright. The split is
  load-bearing — `jest.config.cjs` excludes `/e2e/` by path because Playwright specs import
  `@playwright/test`, "which is not jest-compatible".
- **Setup files and where they run:**
  - `jest.setup.ts` (root, `setupFilesAfterEach` via `setupFilesAfterEnv`) — imports
    `@testing-library/jest-dom`, then polyfills what jsdom 30 lacks: `TextEncoder`/`TextDecoder`
    from `node:util` (jspdf's `iobuffer → fast-png` chain needs them **at import time**),
    `ReadableStream`/`WritableStream`/`TransformStream` from `node:stream/web`,
    a mock `IntersectionObserver` (Framer Motion `whileInView`), `__DEV__ = true` (mobile
    `App.tsx` reads it at import time) and a `performance.now` fallback. Every comment names the
    dependency that forced it.
  - `apps/mobile/jest.setup.cjs` (mobile config only) — silences the
    `Animated: useNativeDriver` warning, and `jest.mock`s `Linking` (both the modern
    `react-native/Libraries/Linking/Linking` path and the legacy `Linking` specifier, `{virtual: true}`),
    `Share` and `Appearance` (defaults to light).
  - `@testing-library/react-native/extend-expect` is also in the mobile `setupFilesAfterEach`.

### 4) Mocking and Isolation Strategy

- **Main mocking approach: `moduleNameMapper`, not `jest.mock`.** The root config maps whole
  modules to **14 hand-written mocks in `__tests__/__mocks__/`** — `react-native`,
  `expo-status-bar`, `expo-modules` (haptics/system-ui), `expo-location`, `expo-notifications`,
  `react-native-gesture-handler`, `-safe-area-context`, `-screens`, `-reanimated`,
  `-svg` (also serving `@shopify/flash-list`), `react-navigation` (all three packages),
  `async-storage`, `netinfo`, `tanstack-react-query`, plus `empty-string.js` for `\.md$` assets.
  The config comments state why: *"Node/jsdom test environments cannot parse react-native's
  Flow-typed sources."* `jest.mock` is used only inside the mobile config's setup file
  (`Linking`, `Share`, `Appearance`, all `{virtual: true}`).
- **Transform-everything policy.** `transformIgnorePatterns: []` — with the reasoning in-file:
  *"Small dependency set, many ESM-only packages (react-markdown's unified/remark ecosystem):
  transform everything instead of maintaining a per-package exception list that breaks on every
  new ESM dependency."* `babel.config.cjs` adds `babel-plugin-transform-import-meta` because
  preset-env transpiles to CJS where `import.meta` is a SyntaxError, and forces
  `sourceType: 'module'` for `backend/**/*.js`.
- **Injectable seams instead of global mocks** where an integration matters:
  `fetchAdvisoryFile(config, { fetchImpl = globalThis.fetch })`
  (`backend/services/kaggleAdvisoryClient.js:170`); Telegram/SMS take an `env` argument
  (`readTelegramConfig(env)`, `backend/alerts/channels/telegram.js:17`); the forecast store has
  `resetForecastStore()` and `FORECAST_STORE_MEMORY=true`; Open-Meteo exports `clearCache()`.
- **Isolation guarantees:**
  - `maxWorkers: '50%'` — *"the API suites import the full Express app (heavy babel transforms of
    ESM deps), and unbounded workers OOM small CI runners."* CI runs the mobile config
    `--runInBand`.
  - Explicit reset hooks per singleton: `resetForecastStore()`, `clearCache()`,
    `resetKaggleCache()`; `ai_fallback_engine.js` exposes breaker state for inspection.
  - `moduleDirectories: ['node_modules', 'frontend/node_modules']` at the root; the mobile config
    deliberately uses **plain upward resolution** (`moduleDirectories: ['node_modules']`) with the
    reason recorded: global module paths *"shadowed Jest 29's nested `pretty-format` with React
    Native's v26 copy and crashed before any native tests could run."*
  - The mobile config pins `react` and `react-test-renderer` to Expo's React **18.2** while the
    web workspace runs React **18.3.1** — *"relying on workspace hoisting causes invalid hooks."*
  - `testPathIgnorePatterns`: `/node_modules/`, `/e2e/`, `/__mocks__/`, `/apps/mobile/`,
    `/manuscript/`; `modulePathIgnorePatterns`: `<rootDir>/manuscript/` (a directory that does
    not exist at HEAD).
  - The dispatcher mutates the request in place when stripping routing artefacts, so
    **a test harness that reuses one request object across invocations must rebuild it per call**
    (`serverless/dispatch.js` header).
- **Common failure modes in these tests — all three are documented in-repo, which is unusual and
  worth preserving:**
  1. **cwd-relative Babel resolution.** `apps/mobile/jest.config.cjs` once had
     `configFile: './babel.config.cjs'`, which Jest resolves against the **current working
     directory**, not `rootDir`. From the repo root the RN preset never applied and every suite
     died in `@react-native/js-polyfills/error-guard.js` with *Missing semicolon* — a Flow parse
     error that reads like a broken dependency. Fixed by resolving against `__dirname`.
  2. **Open handles after the RN run.** Jest reports *"did not exit one second after the test run
     has completed"* and suggests `--detectOpenHandles`. **Reproduced here**: the run needed
     `--forceExit`, and the captured stack points at
     `apps/mobile/src/hooks/useSavedPlaces.tsx:87` (`setIsReady` after an async resolve) through
     `react-test-renderer`'s `dispatchSetState`. Owner Action 13 tracks removing the flag.
  3. **Conditional skips that look like coverage.** Three suites gate themselves on a built
     `frontend/dist`: `const built = existsSync(join(dist,'index.html')); const maybe = built ?
     describe : describe.skip` (`__tests__/seoFoundations.test.js:32-33`,
     `__tests__/statusPagePrerender.test.js:30-31`, `__tests__/structuredData.test.js:176`).
     Without a build they skip silently — this is exactly why `ci.yml`'s `verify` job (the only
     job that builds) re-runs those three explicitly in a *"Post-build surface checks"* step.

## Extended Sections (Optional)

### Framework-specific suite patterns worth copying

- **Ledger + ratchet.** A gate is a Jest suite **plus** a frozen JSON baseline in `data/design/`
  carrying a `why` block that names the audit finding it came from. The assertion is always
  `toBeLessThanOrEqual(BASELINE)`. `__tests__/iconFamily.test.js:195` is the canonical example:
  `BASELINE_IMPORTERS = 61`, measured **54** today. `data/design/svg-paint-baseline.json` states
  the rule outright: *"Each one is frozen in its light-mode value and cannot follow the theme.
  Counts may only go down."*
- **Build-conditional suites that announce themselves.** `if (!built) { … }` prints why the suite
  is skipping rather than skipping silently (`__tests__/seoFoundations.test.js:35`).
- **Config-shape tests as deployment guards.** `__tests__/modelArtifactsNotServed.test.js` asserts
  that no rewrite, redirect or hosting root points at `Models/` — *"the deployment configs were
  only protected by convention: nothing failed if a rewrite … started pointing at the artifacts."*
  It checks configuration, not the live deployment, and says so.
- **Pure decision functions extracted for testability.**
  `rateLimitDecision(entry, {limit, windowMs}, now = Date.now())` — *"Pure decision function, so
  the window arithmetic is testable without an HTTP server"*
  (`backend/middleware/serverlessGuard.js:89-101`).
- **Exit codes as a tested contract.** `scripts/fetch_kaggle_advisory.mjs` uses
  `0 fresh / 2 unchanged-or-stale / 1 failed`, the workflow branches on it, and the workflow's own
  comment forbids `set -e` on that step so the branch can read the code.
  `scripts/tests/test_workflows.py` parses `.github/workflows/*.yml` with PyYAML and asserts the
  shape — CI configuration is itself under test.

### Detailed mock recipes per dependency type

| Dependency type | Recipe | Where |
|---|---|---|
| React Native / Expo | Static module mock via `moduleNameMapper` → `__tests__/__mocks__/*.js` | root `jest.config.cjs` |
| `.md` article imports | `'\.md$' → __tests__/__mocks__/empty-string.js` | root `jest.config.cjs` |
| `Linking` / `Share` / `Appearance` | `jest.mock(..., { virtual: true })` with both the modern `react-native/Libraries/...` and legacy specifiers | `apps/mobile/jest.setup.cjs` |
| `fetch` (Kaggle, Open-Meteo, telemetry) | **Parameter injection**: `{ fetchImpl = globalThis.fetch }` — no global patching | `backend/services/kaggleAdvisoryClient.js:170` |
| Env-driven config | Functions take an `env` argument defaulting to `process.env` | `backend/alerts/channels/{telegram,sms}.js`, `backend/services/kaggleAdvisoryClient.js:44` |
| Firestore | `FORECAST_STORE_MEMORY=true` + `resetForecastStore()`; `firebase-admin` stubs are tolerated (`setLogLevel` wrapped in `try/catch` because it *"is unavailable in some firebase-admin stubs used by tests"*) | `backend/forecastStore.js:139`, `backend/db.js:24-27` |
| Express handlers | `node-mocks-http` for unit-level, `supertest` against the real app for integration | `__tests__/api/*` |
| Serverless dispatch | Rebuild the request object per invocation (the dispatcher mutates it in place) | `serverless/dispatch.js` header |
| Playwright browser | `QA_CHROMIUM_PATH` → an npm-published Chromium, single worker | `playwright.qa.config.ts` |

### Test performance notes

- Coverage instrumentation costs ~2.4× wall clock here (59 s → 140 s), which is why CI splits
  coverage across the backend and frontend jobs instead of collecting it once.
- `maxWorkers: '50%'` is an OOM guard, not a speed choice; the API suites are the heavy ones
  because they import the full Express app and drag the ESM dependency graph through Babel.
- `transformIgnorePatterns: []` means **every** `node_modules` file imported by a suite is
  transpiled. That is the deliberate trade for never maintaining an ESM exception list; the cost
  shows up as the 60-70 s floor on a cold run.
- The mobile run is fast (16.3 s) but does not exit — the `--forceExit` in CI is what keeps the
  job from hanging, and it is the flag Action 13 wants removed.
