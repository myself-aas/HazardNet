## Core Sections (Required)

### 1) Architectural Style

- **Primary style:** a pipeline publishes snapshots as committed static files. Those files are
  served at the edge by Cloudflare Pages, as static assets and through thin Pages Functions. The
  same handlers have a second, portable Node runtime that is not deployed. Shared contracts and
  rules live in a monorepo core.
- **Why this classification:**
  1. **The authoritative data path commits its output to git.**
     `.github/workflows/public_daily_advisories.yml` runs every 3 hours. It polls Kaggle,
     rebuilds the public artifacts, and commits up to 16 paths with `[skip ci]`
     (`frontend/public/data/*`, `backend/data/forecasts/*`, `frontend/src/content/generated-routes.json`,
     test fixtures). It then POSTs the Pages deploy hook. There is no database in the read path.
  2. **The edge API reads those same artifacts, not a store.** For example,
     `functions/api/v1/forecasts/bulk.ts` calls `loadForecastSnapshot(env, request)`, which
     fetches the deployed JSON through the `ASSETS` binding. Its header states the split:
     "Firestore-first there [Node], the committed snapshot here".
  3. **Scheduling belongs to GitHub Actions.** There is no queue, broker or worker anywhere
     (scan §CONTAINERS: none). The cron workflows are `public_daily_advisories` (`15 */3 * * *`),
     `site-health` (`*/30 * * * *`) and `secret-rotation-audit` (`15 7 1 * *`). The rest are
     dispatch-only or PR-triggered.
- **Primary constraints:**
  - **The publication policy is binding.** `docs/PUBLICATION_POLICY.md` and `PRODUCT.md` require
    model code, dataset procedures, training and severity derivation to stay research-private.
    Inference therefore runs in a Kaggle notebook outside this repository, and no ML framework
    appears in any manifest. `Models/` is metadata only and is blocked from serving.
  - **Free tier only.** `docs/ops/owner-actions.md` §Cost constraints and the 2026-10-26 decision
    log withdraw paid dependencies. That is why rate limiting is per-instance, telemetry goes to
    Analytics Engine, and no Durable Objects are used.
  - **Low-end Android on 2G/3G is the design target** (`PRODUCT.md` §Operating Context). Every
    page is `lazy()`, there is a bundle budget (`scripts/check-bundle.mjs`), a 50 KiB Bangla font
    budget, and a low-bandwidth attribute is set before first paint (`frontend/src/main.tsx`).
  - **Two runtimes, one behaviour.** Edge handlers import their validation and envelopes from
    `backend/utils/*`. Node handlers import the same modules. Modules shared with the edge must
    avoid `node:*` built-ins.

### 2) System Flow

**Flow A: the published-number path (the product's spine)**

```text
Kaggle notebook (outside the repo) publishes a dataset version
  -> .github/workflows/public_daily_advisories.yml   (cron 15 */3 * * *)
     -> scripts/fetch_kaggle_daily_public.mjs        exit 0 new / 2 no new Ready version / other = fail
     -> scripts/build_public_daily_advisories.mjs    -> frontend/public/data/daily-advisories-v1.json
                                                        (field-whitelisted, 64 × 15 = 960 rows, 5 tiers)
     -> scripts/check_public_daily_asset.mjs --require
     -> scripts/sync_daily_to_forecasts.mjs          -> forecasts-latest.json, alerts-latest.json,
                                                        freshness.json, backend/data/forecasts/*, …
     -> scripts/build_daily_report.mjs               -> frontend/public/reports/
     -> scripts/capture_edge_fixtures.mjs            -> __tests__/fixtures/*.js
     -> jest (3 suites) -> npm run build -> npm run audit:pages:strict
     -> cmp public/data/* vs frontend/dist/data/*    (served copy == committed copy)
     -> git commit [skip ci] + push
     -> curl -X POST $CF_PAGES_DEPLOY_HOOK           (skipped with a summary note if unset)
  -> Cloudflare Pages builds main: npm ci --legacy-peer-deps && npm run build -> dist/
```

State at HEAD (committed artifacts): `daily-advisories-v1.json` run `kaggle-v55-85ab01fb7b04`,
`generatedAt 2026-11-15T22:53:54Z`, **`expiresAt 2026-11-17T10:53:54Z`**, 64 districts × 15
days = 960 rows, `modelVersion 2.1.9+model.0bb5bdaf1789`. Tiers: 949 `WATCH`, 9 `EXTREME`,
2 `SEVERE`, all non-`WATCH` rows marked `requiresReview: true`. `backend/data/forecasts/manifest.json`
has `prediction_date 2026-11-15`, `row_count 128`. `alerts-latest.json` assessed 64 districts and
has 62 `PUBLISHED` `WATCH` alerts and 0 `WARNING`/`SEVERE`.

The older `daily_advisory_ingest.yml` (128-row CSV path) is **dispatch-only** ("legacy").
`deployment.md` §4 says it "never imports this daily export".

**Flow B: a browser read**

```text
frontend/src/main.tsx -> App.tsx (ErrorBoundary > AuthProvider > QueryClientProvider > Router; 80 routes)
  -> page/hook (useForecasts, useAlertsData, useKaggleAdvisories, …)
     -> frontend/src/lib/{forecasts,alerts,dailyAdvisories,freshness}.ts
          static:  GET /data/forecasts-latest.json?fresh=<ts>  (cache: 'no-store')
                   GET /data/daily-advisories-v1.json, /data/alerts-latest.json, /data/freshness.json
          API:     GET /api/v1/alerts, /api/v1/forecasts/{bulk,metadata}, /api/v1/weather …
                   (paths from @hazardnet/api API_PATHS; alerts falls back to ALERTS_SNAPSHOT_URL)
     -> @hazardnet/core contracts (Zod) shape/validate rows
  -> TanStack Query cache -> render; every page in data/design/four-state-baseline.json
     must cover loading / empty / error+retry / success
```

**Flow C: an edge API request** (example `GET /api/v1/forecasts/bulk`)

```text
Cloudflare Pages: _routes.json includes "/*", excludes /assets/*, /data/*, static extensions
  -> functions/_middleware.ts  onRequest: await next(), then applySecurityHeaders()
                               (from backend/security/httpHeaders.js), RFC 9728 challenge on 401
  -> functions/api/v1/forecasts/bulk.ts  onRequestGet (only GET exported -> Pages answers 405 otherwise)
       parseBulkQuery()            backend/utils/forecastServe.js      (same 400 as the Node runtime)
       loadForecastSnapshot()      backend/utils/forecastSnapshotServe.js -> env.ASSETS.fetch(/data/…)
       bulkEnvelopeFromSnapshot()  -> respond(..., { cache: CACHE.noStore })  backend/edge/response.js
       on asset failure: console.error + 503 "forecast snapshot is unavailable" (path not echoed)
```

**Flow D: the Node runtime (self-host, not deployed)**

```text
api/v1/forecasts/[action].js -> createDispatcher (serverless/dispatch.js)
  -> guardRequest(bucket:'read')   backend/middleware/serverlessGuard.js (per-instance limits)
  -> routeSegment() — path wins, ?action= fallback; stripRouteParam()
  -> () => import('../../../serverless/v1/forecasts/bulk.js')   (literal, per request)
  -> backend/utils/forecastServe.js -> backend/forecastStore.js
       Firestore (client SDK via backend/db.js) with circuit breaker -> committed snapshot fallback
  -> catch: JSON 500 "internal server error"
```

In this pass every literal `import('…')` in the six `api/**` route tables resolved to an
existing file.

| Pattern | Where found | Why it exists |
| --- | --- | --- |
| **Committed snapshot as the database** | `frontend/public/data/*.json`, read by both the browser and `functions/**` via `ASSETS` | No paid store; every number travels with its provenance fields (`run`, `generatedAt`, `expiresAt`, `modelVersion`, `inputSha256`) |

| **Route register with dated dispositions** | `docs/ops/route-register.json` + `__tests__/routeReachability.test.js` | Every frontend-called route is either an edge file or a recorded decision |
| **Provider cascade + circuit breaker** | `backend/utils/ai_fallback_engine.js:545` — `gemini_primary` → `gemini_secondary` → `openrouter` → `groq` → `huggingface`, skipping unhealthy providers; validated cache | Free-tier LLM quotas |

| **Policy as data, versioned** | `backend/alerts/policy.js` (`policy_version` stamped on each alert, e.g. `alert-policy/1.0.0`) | A threshold change is a reviewable config change |

| **Ratchet baselines** | `data/design/*.json` + `scripts/check-*.mjs` | Debt only shrinks |
| **Self-describing artifacts** | `freshness.json` (`what_this_is`, `honesty`, per-source `state`/`age_hours`), route register `what_this_is` | `PRODUCT.md` principle 1 |

### 5) Known Architectural Risks

- **The daily artifact expires on a clock, and only one producer refreshes it.**
  `daily-advisories-v1.json` carries `expiresAt` (36 h after `generatedAt`, from
  `SLO_HOURS.DAILY_ADVISORIES`). At HEAD it expires **2026-11-17T10:53Z**. If Kaggle publishes
  no new Ready version, the publisher exits 2 ("public site unchanged") and the site serves an
  expired artifact. Since 2026-11-17 (owner decision) the district daily page and
  `DailyOutlookEntry` show "Last updated [time]" and an "Under development" flag beside the
  existing not-current warning; nothing yet alerts when the served file is past `expiresAt`.
- **The edge API is snapshot-backed while the Node API is store-backed.** The same URL can
  return different rows depending on host. This is accepted and documented
  (`backend/utils/forecastSnapshotServe.js`), but nothing keeps Firestore in step except
  `scripts/mirror_public_daily_to_firestore.mjs`. Whether any workflow invokes that script is
  `[TODO]`: no workflow references it.
- **The site-health probe flaps.** Since 2026-10-17 the probe has committed 21 "fail" and 22
  "pass" records. The latest (`data/site-health/latest.json`, 2026-11-16T01:12Z) fails only
  `runtime_paths`: `/api/v1/weather` returned 502 without `daily.temperature_2m_max[0]`, and the
  batch POST check failed. Weather is the only edge route with a live upstream (Open-Meteo).
- **There are two severity vocabularies.** The public daily artifact publishes 5 *advisory
  tiers*, including `EXTREME`/`SEVERE` flagged `requiresReview`, with "no person approves each
  run" (`deployment.md` §4). The alert engine publishes 4 *alert levels* and refuses
  auto-publish above `WATCH`. `PRODUCT.md` names 4 tiers (SEVERE/WARNING/WATCH/NORMAL).
  `CLAIMS.md` CLM-009 names 5. See CONCERNS §6 Q1.
- **The edge bundle imports from `backend/`.** Pages watch paths must include `backend/**`
  (`deployment.md` §2). A `node:*` import added to a shared module would break the Functions
  build, not the Node runtime. `[TODO]`: no test found that asserts edge-shared modules are free
  of `node:*`.
- **The Vite build shim is load-bearing.** `frontend/vite.config.ts` `leafletGlobalShim()` works
  around Rolldown's lazy CommonJS init, which white-screened production. Dev mode cannot detect
  a regression. Only the `test-e2e` CI job (build → preview → Playwright) can.
- **`LiveMapView.tsx` is 2,467 lines** and is the third most-churned source file (28 commits in
  90 days).
