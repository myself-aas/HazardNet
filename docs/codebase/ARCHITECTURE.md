## Core Sections (Required)

### 1) Architectural Style

- **Primary style: build-time-published snapshots, served by two interchangeable HTTP runtimes,
  over a monorepo with a shared contract + design core.** Not layered-clean-architecture, not
  event-driven: there is no queue, no broker and no long-running worker anywhere in the tree
  (scan §CONTAINERS & ORCHESTRATION: none; no `kafka`/`amqp`/`sqs`/`pubsub` dependency in any
  manifest).
- **Why this classification:**
  1. The authoritative data path **commits its own output to git**. `daily_advisory_ingest.yml`
     fetches a CSV, rebuilds four artifacts and `git push`es them, then triggers a deploy.
     The frontend's primary read is a static file: `FORECAST_SNAPSHOT_URL = '/data/forecasts-latest.json'`
     (`frontend/src/lib/forecasts.ts:419`).
  2. Scheduling is **the CI platform's**, not the app's — cron-triggered workflows
     (`daily_advisory_ingest` 05:30 UTC, `site-health` every 30 min,
     `secret-rotation-audit` monthly), tag/main-triggered release workflows
     (both retired 2026-10-26 — see `.github/workflow-templates/`), and dispatch-only ones
     (`verify-secrets`, `Firebase-Store-Verify`, and — at HEAD — `live-wind-update`).
  3. The same API surface is implemented twice — Express (`backend/routes/**`) and Vercel
     functions (`serverless/**`) — and parity is maintained by **sharing the logic modules**, not
     by generating one from the other. **At HEAD this parity is severed**: 17 of 18 serverless
     handler modules were deleted while the dispatchers and their tests still reference them
     (see §5).
- **Primary constraints (all three shape the design visibly):**
  - **Vercel Hobby: ≤12 Serverless Functions.** The entire `api/` ↔ `serverless/` split exists
     for this. Measured **6/12** (`node scripts/check-vercel-functions.mjs`).
  - **`docs/PUBLICATION_POLICY.md` is binding:** model code, dataset collection, training,
     benchmarking and severity derivation are research-private. Inference therefore lives in a
     Kaggle notebook **outside this repository**; no ML framework appears in any manifest.
     Between `b321083f` and HEAD this policy appears to have driven a second pruning round —
     the `.tflite` binaries, the pytest gate suite (`scripts/tests/`), and ~35 scripts were
     removed (§5 rows 1-2).
  - **Low-end Android on 2G/3G is the design target, not a fallback** (`PRODUCT.md` §Operating
     Context). Enforced mechanically: 800 KiB gzip per chunk / 1,600 KiB total
     (`scripts/check-bundle.mjs`), route-level `lazy()` for every page, a 50 KiB Bangla
     webfont budget (`scripts/check-font-payload.mjs`).

### 2) System Flow

```text

     -> scripts/fetch_kaggle_advisory.mjs        --wait-minutes 12 --max-age-hours 36
                                                  exit 0 fresh / 2 unchanged-or-stale / 1 failed
     -> scripts/process_advisory_ingest.mjs      validate -> map advisory columns -> write
        backend/data/forecasts/{hazardnet_forecasts_latest.csv,.json,manifest.json}
     -> scripts/rehearse_alert_engine.mjs        -> /tmp/advisory-ingest/alert-run.json
     -> scripts/build_alert_snapshot.mjs         -> frontend/public/data/alerts-latest.json
     -> scripts/build_freshness_artifact.mjs     -> frontend/public/data/freshness.json
  -> node --test __tests__/advisoryPipeline.test.js
  -> git commit + git push (backend/data/forecasts/, forecasts-latest.json,
                            alerts-latest.json, freshness.json)
  -> npx vercel deploy --prod   (only if artifacts changed AND VERCEL_TOKEN is set)
  -> (retired 2026-10-26) scripts/notify_ops.mjs -> Slack #hazardnet-ops
     wiring now lives in .github/workflow-templates/hazardnet-ops-slack-notify.yml
```

State at HEAD: **the pipeline is producing again.** Latest committed run:
`prediction_date 2026-10-24`, `row_count 128` (the CLM-005 contract, met),
`model_version 2.1.9+model.0bb5bdaf1789` stamped (`backend/data/forecasts/manifest.json`);

**Flow B — a browser read**

```text
frontend/src/main.tsx -> App.tsx (76 <Route>, all pages lazy())
  -> page/hook (e.g. useForecasts, useKaggleAdvisories)
     -> frontend/src/lib/forecasts.ts
          primary:  GET /data/forecasts-latest.json   (committed snapshot, cache: 'no-store')
          alternate: GET /api/v1/forecasts/metadata + /api/v1/forecasts/bulk?horizon=7_days
     -> @hazardnet/core contracts (Zod) validate/shape the row
     -> @hazardnet/design-system (apple.ts) resolves every colour/type/radius/motion value
  -> TanStack Query cache -> React render -> four-state surface (loading/empty/error+retry/success)
```

At HEAD the **primary** read is fresh (snapshot dated 2026-10-24) while the **alternate**
read is broken — `/api/v1/forecasts/*` handlers were deleted, so the page's live-API panel
fails closed (measured in the `FrontDoor` test output: *"live API: HTTP 503"* beside a
correct snapshot panel). This is the failure-soft design working as intended around a real
outage.

**Flow C — a serverless API request**

```text
GET /api/v1/forecasts/bulk
  -> Vercel matches api/v1/forecasts/[action].js        (one of 6 functions)
  -> serverless/dispatch.js: routeSegment(req,'action',table)
       path is the source of truth; ?action= is the fallback for direct invocation;
       BOTH are stripped before the handler runs
  -> guardRequest(...)                                   backend/middleware/serverlessGuard.js
       per-instance, cost-bucketed rate limits + metering
  -> () => import('../../../serverless/v1/forecasts/bulk.js')   (per-request, literal specifier)
       *** MODULE NOT FOUND AT HEAD — the file was deleted; the dispatcher's catch
       answers JSON 500 "internal server error" (serverless/dispatch.js:76-82) ***
  -> backend/utils/forecastServe.js                      the SAME module Express uses
  -> backend/forecastStore.js -> Firestore, falling back to the committed JSON snapshot
  -> JSON response; 5xx text is replaced by backend/utils/clientError.js
```

Six steps, all file-backed: match → route → guard → lazy-load → shared serve module → store.
Step 4 is severed at HEAD for 17 of 18 handlers (CONCERNS §1).

### 4) Reused Patterns

| Pattern | Where found | Why it exists |
|---------|-------------|---------------|
| **Dispatcher / front-controller** | `serverless/dispatch.js` + all six `api/**` entry points | The 12-function budget: one function per URL *family*, dispatching to handlers Vercel never scans |
| **Per-request lazy import with literal specifiers** | `api/[endpoint].js`, `api/v1/[resource].js`, `api/v1/alerts/[action].js`, `api/v1/forecasts/[action].js`, `api/chat/[action].js` | Fault isolation (a module-level throw must not fail the family) and cold start — the isolation works: at HEAD the deleted handlers 500 individually while `v1/historical` still resolves |
| **Shared-module parity** | `backend/utils/forecastServe.js`, `backend/utils/chatService.js`, `backend/middleware/serverlessGuard.js` (imported by `serverless/dispatch.js`) | Two runtimes, one behaviour — parity by construction rather than by test |
| **Provider cascade + circuit breaker** | `backend/utils/ai_fallback_engine.js` (534 L) — `cascadeProviders` array, per-provider timeout, `circuitBreakers` with 45 s cooldown, 429 trips the breaker and falls through | Free-tier LLM quotas are the norm here; a hung or quota-exhausted upstream must not eat the whole request |
| **Deterministic fallback** | `backend/utils/ai_fallback_engine.js` → heuristic engine; `backend/server.js` warns when `GEMINI_API_KEY` is unset rather than failing | The advisory surface must render with no AI provider at all |
| **Singleton with a reset hook** | `backend/forecastStore.js` (`cachedStore`, `getForecastStore()`, `resetForecastStore()`) | One store per process, testable |
| **Ratchet / frozen-baseline gate** | `data/design/*.json` (6 baselines + icon registry) + `scripts/check-{token-compliance,css-important,svg-tokens,design-residue,contrast}.mjs` | Debt is enumerated, frozen and only allowed to shrink |
| **Fail-closed on missing config** | `backend/utils/apiKeyAuth.js` (503 when `BACKEND_API_KEY` unset), `backend/middleware/cors.js` (production rejects cross-origin when `FRONTEND_ORIGIN` unset) | A misconfiguration must stop the request, not silently widen access |
| **Startup assertion (non-fatal)** | `backend/server.js` — `problems[]` vs `warnings[]`, logged before the app listens | Loud early signals for misconfig while local dev still boots |
| **Four-state surface** | `data/design/four-state-baseline.json` — one entry per file in `frontend/src/pages`, four states each (loading / empty / error+retry / success) | "Absent is reported as absent" (`PRODUCT.md` principle 2) |
| **Client-safe error boundary** | `backend/utils/clientError.js` — 4xx messages pass through, **5xx always generic** + server-side stack log; 13 call sites at HEAD (was 21; the deleted serverless handlers carried the rest) | Written after a 2026-09-17 live audit found raw driver text reaching clients |
| **Artifact self-description** | `frontend/public/data/freshness.json` (`schema`, `built_at`, `generated_by`, `what_this_is`, per-source `state`/`reason`/`age_hours`) — at HEAD itself **stale**, see §5 | Every published number carries its provenance (`PRODUCT.md` principle 1) |
| **Root ErrorBoundary + `lazy()`** | `frontend/src/App.tsx`, `frontend/src/components/ErrorBoundary.tsx` | Route-level code splitting and containment of a failed chunk |

## Extended Sections (Optional)

### Vercel serverless surface (the 12-function budget)

**The constraint.** The Vercel Hobby plan allows **at most 12 Serverless Functions per
deployment**, and every file under `api/` is one function. This repository serves more public
URLs than that. A file per URL does not fit.

**The design.** `api/` holds one entry point per URL *family*; each is a thin
`createDispatcher({ param, entry, routes })` call. The handlers live in `serverless/`, a
directory Vercel never scans for functions (only `api/` is).

**Measured: 6 of 12 functions deployed, 6 left on the budget** (`node scripts/check-vercel-functions.mjs`):

| # | Function file | Family | Dispatches to | State at HEAD |
|---|---|---|---|---|
| 1 | `api/[endpoint].js` | top-level | `serverless/{forecasts,historical,ingest,metrics,predict}.js` | **all 5 deleted** |
| 2 | `api/chat/[action].js` | chat | `serverless/chat/{query,sample-questions}.js` | **both deleted** |
| 3 | `api/v1/[resource].js` | v1 resources | `serverless/v1/{alerts/index,historical,kaggle,telemetry,weather}.js` | only `historical.js` survives |
| 4 | `api/v1/alerts/[action].js` | alerts actions | `serverless/v1/alerts/{evidence-card,policy,review,run}.js` | **all 4 deleted** |
| 5 | `api/v1/forecasts/[action].js` | forecast actions | `serverless/v1/forecasts/{bulk,history,metadata}.js` | **all 3 deleted** |
| 6 | `api/v1/weather/batch.js` | static sibling | itself (static wins over a dynamic segment) | present |

**Routing contract** (from `serverless/dispatch.js`, 86 L at HEAD):

- The **path is the source of truth** for the segment; the query parameter is the fallback
  (`routeSegment`). **Both are stripped from the request before the handler runs**
  (`stripRouteParam`), so a handler can never mistake a routing artefact for a user-supplied
  `?action=`. The stripping mutates the request in place — a test harness that reuses one
  request object must rebuild it per call.
- Guard runs first (`guardRequest`, from `backend/middleware/serverlessGuard.js`); an
  unmatched path gets a **JSON 404** (`no endpoint "<key>"`) with rate-limit headers.
- A loader that throws — which at HEAD is every deleted handler — is answered with JSON 500
  `internal server error` (`dispatch.js:76-82`), per route, without touching the rest of the
  family. The fault-isolation design is visibly doing its job at HEAD.
- **Static siblings win** over a dynamic segment; only one segment is matched.

**The gate.** `scripts/check-vercel-functions.mjs` (`HOBBY_FUNCTION_LIMIT = 12`,
`HEADROOM_WARNING = 2`) runs in CI. **Gap:** it counts function *files*, not whether the
handlers they import exist — at HEAD it passes 6/12 over a severed surface. A route-table
integrity check (every literal `() => import('…')` resolves) is the missing gate.

**Adding an endpoint:** put the handler in `serverless/`, add one entry to the relevant
family's `routes` table with a **literal** `() => import('…')` specifier (so the bundler can
trace it), then run `npm run check:functions`. Only a new URL *family* consumes budget.

### Startup / initialisation order (self-host)

`backend/server.js`, in order: `dotenv.config()` → `assertEnvironment()` IIFE (problems/warnings)
→ `express()` → `app.disable('x-powered-by')` → `app.set('trust proxy', 1)` →
`helmet({frameguard: deny, hsts 2 y + preload, contentSecurityPolicy: {reportOnly: !cspEnforce,
directives: cspDirectivesFromString()}})` → `requestId` → `corsMiddleware()` →
`express.json({limit:'10mb'})` → the manual header middleware (including the RFC 9727
`Link: rel="api-catalog"` and `WWW-Authenticate: Bearer resource_metadata=…` advertised on
**every** response) → `.well-known` endpoints → routers → `/health` → `/metrics` →

### Failure modes and resilience posture

| Failure | Posture | Evidence |
|---|---|---|
| LLM provider down / quota-exhausted | Per-provider timeout, circuit breaker with 45 s cooldown, cascade to the next provider, final deterministic heuristic fallback | `backend/utils/ai_fallback_engine.js` |
| Firestore unprovisioned / offline / 0 records | Automatic fallback to the committed static snapshot; `firestoreAvailable` flag re-probes | `backend/forecastStore.js` |
| `BACKEND_API_KEY` unset | **Fail closed**: privileged endpoints return 503 | `backend/utils/apiKeyAuth.js`, `backend/server.js` |
| `FRONTEND_ORIGIN` unset in production | **Fail closed**: cross-origin browser requests rejected, not reflected | `backend/middleware/cors.js`, `backend/server.js` |
| Kaggle CSV stale (>36 h) or unchanged | The **fetch step** fails with the publication age; a scheduled no-update exits distinctly, a manual rehearsal stays a successful no-op | `daily_advisory_ingest.yml`, `scripts/fetch_kaggle_advisory.mjs` |
| Leaflet plugin throws in a production build | Build-time `leafletGlobalShim()` pins initialisation order inside the plugin module | `frontend/vite.config.ts` |
| A page chunk fails to load | Root `ErrorBoundary`; per-surface four-state (loading/empty/error+retry/success) | `frontend/src/App.tsx`, `data/design/four-state-baseline.json` |
| A district the run did not cover | Reported as absent in words, carries `robots: noindex,follow` and no sitemap entry — never rendered as zero | `PRODUCT.md` principle 2, `frontend/scripts/prerender.mjs` |
| Cloudflare challenges the probe | The probe sends `x-hazardnet-probe` (**owner WAF skip rule in place — `edge_challenged: false` at the 2026-10-24 run**) and records `edge_challenged` so a blocked probe is distinguishable from a down site | `.github/workflows/site-health.yml`, `data/site-health/latest.json` |
| **A serverless handler module is missing** | Per-route JSON 500 via the dispatcher's catch; the rest of the family keeps serving | `serverless/dispatch.js:76-82` — **exercised for real at HEAD** |
