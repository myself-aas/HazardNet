## Core Sections (Required)

### 1) Architectural Style

- **Primary style:** a **dual-runtime layered monolith with a scheduled batch pipeline and a
  statically published read surface**. Concretely: an HTTP delivery layer that exists twice
  (Express `backend/server.js` for self-host, Vercel functions `api/**` → `serverless/**` for
  production) over one shared domain layer (`backend/alerts/**`, `backend/utils/**`), a React SPA
  client, and GitHub Actions workflows that run the data pipeline and commit its artifacts back
  into the repository.
- **Why this classification:**
  - Two entry stacks, one domain: `serverless/v1/forecasts/bulk.js` is a thin wrapper over
    `backend/utils/forecastServe.js` + `backend/forecastStore.js`, and its header comment states
    the goal explicitly — "the response shape is identical to `backend/routes/forecasts.js` by
    construction". The same split is documented in `backend/utils/chatService.js`.
  - Layering is physical: `routes/` → `services|utils/` → `alerts/*` (domain) → store (`db.js`).
  - Batch/pipeline: `.github/workflows/daily_advisory_ingest.yml` (cron `30 5 * * *`) and
    `site-health.yml` (cron `*/30 * * * *`) run scripts that write committed artifacts
    (`frontend/public/data/*.json`, `data/site-health/latest.json`).
  - Static publishing: `frontend/scripts/prerender.mjs` prerenders routes from
    `frontend/src/content/site-routes.json` and `generated-routes.json`; the client falls back to
    committed snapshots when the API is unreachable (`frontend/src/hooks/useForecasts.ts`).
- **Primary constraints:**
  1. **Vercel Hobby's 12-Serverless-Function budget** — the whole `api/` shape (one entry file per
     URL family, handlers in `serverless/`, `createDispatcher` in `serverless/dispatch.js`) exists
     for this. Enforced by `scripts/check-vercel-functions.mjs` (currently 6/12).
  2. **Publication policy** — model code, training procedure and severity derivation are
     deliberately *not* published (`docs/PUBLICATION_POLICY.md`, `README.md`); the repo ships
     results and outputs only, and `backend/server.js` 404s every `Models/**` path.
  3. **Honesty/verifiability constraints encoded in code** — the alert policy refuses to
     auto-publish above `WATCH` and refuses `WARNING` without calibrated probability
     (`backend/alerts/policy.js`); public numeric claims are gated by `scripts/verify_claims.mjs`
     against `CLAIMS.md`; artifact builders must "never invent" a value
     (`scripts/build_freshness_artifact.mjs`).

### 2) System Flow

**A. Reading a forecast (the main public path)**

```text
browser (React)
  -> frontend/src/hooks/useForecasts.ts (TanStack Query)
  -> GET /api/v1/forecasts/bulk?horizon=7_days
  -> [dev] Vite proxy :3000 -> :3001            | [prod] Vercel edge
  -> backend/routes/forecasts.js GET /bulk      | api/v1/forecasts/[action].js -> serverless/dispatch.js
                                                |   -> serverless/v1/forecasts/bulk.js
  -> backend/utils/forecastServe.js (parse/validate, shared by both runtimes)
  -> backend/forecastStore.js (singleton store)
  -> backend/db.js (Firestore, named database id from firebase-applet-config.json)
  -> JSON { horizon, count, generated_at, data_source, forecasts[] }
```

1. `loadForecasts()` fetches the bulk endpoint with `cache: 'no-store'` and validates the payload
   with `parseBulkResponse()` (`frontend/src/lib/forecasts.ts`).
2. On any failure it falls back to the committed snapshot `/data/forecasts-latest.json`
   (`fetchStaticForecastSnapshot`), and only throws when both are unavailable — at which point
   callers degrade to the static `ALL_64_DISTRICTS` baseline
   (`frontend/src/data/bangladeshDistricts.ts`, `useLiveDistricts`).
3. Server-side, both runtimes call the same `parseBulkQuery()` and the same store, so the two
   deployments cannot return different shapes (`serverless/v1/forecasts/bulk.js`).
4. Rate limiting is applied per runtime: `express-rate-limit` on the Express path
   (`backend/middleware/rateLimit.js`) and `guardRequest()` (in-memory, per-instance buckets) on
   the serverless path (`backend/middleware/serverlessGuard.js`), because Express middleware never
   runs on Vercel.

**B. Producing and publishing data (the pipeline)**

```text
GitHub Actions (daily_advisory_ingest.yml, 05:30 UTC)
  -> scripts/validate_advisory_csv.mjs / scripts/process_advisory_ingest.mjs / scripts/ingest_forecast_csv.mjs
  -> backend/utils/csvIngestion.js + backend/utils/forecastRow.js (row contract, 128 rows = 64 districts x 2 horizons)
  -> backend/forecastPersistence.js (Firestore transaction, privileged writer, 500-op limit)
  -> scripts/build_forecast_snapshot.mjs / build_alert_snapshot.mjs / build_freshness_artifact.mjs / build_content_engine.mjs
  -> committed artifacts under frontend/public/data/ + backend/data/forecasts/
  -> git push -> Vercel build (vite build + prerender) -> deploy
```

**C. The alert lifecycle (the only stateful write path with human gates)**

```text
forecastStore rows
  -> backend/alerts/assess.js assessBatch() -> one assessment per (district, horizon, target_date, hazard)
  -> backend/alerts/service.js runAlertEngine(): DRAFT (NO_ALERT stays DRAFT, never published)
  -> auto-publish only when level <= max_auto_publish_level (WATCH) and inside ALERT_AUTO_PUBLISH_MINUTES
  -> otherwise PENDING_REVIEW -> POST /api/v1/alerts/:id/review (named duty officer, backend/alerts/lifecycle.js)
  -> PUBLISHED | REJECTED -> backend/alerts/notify.js -> channels/sms.js (bulksmsbd / greenweb) + channels/telegram.js
  -> backend/alerts/report.js (evidence card, CSV, markdown) + /export.csv
```

**D. The AI advisor**

```text
frontend/src/components/ChatBot.tsx -> POST /api/chat/query
  -> backend/routes/chat.js (Express) OR serverless/chat/query.js (Vercel)
  -> backend/utils/chatService.js (single shared implementation)
       -> backend/services/localKnowledge.js  (RAG over skills/** + govt office directory)
       -> backend/utils/ai_fallback_engine.js (6-tier cascade + circuit breakers + 10-min TTL cache)
       -> backend/utils/gemini_grounding.js   (Google Maps / Search grounding when intent detected)
```

| `backend/alerts/**` | The alert domain: policy-as-data (`policy.js`), assessment (`assess.js`), state machine (`lifecycle.js`), append-only store (`store.js`), evidence/report (`report.js`), notification + channels, digest, calibration | HTTP/plumbing | `backend/alerts/service.js` (composition diagram in its header) |

### 4) Reused Patterns

| Pattern | Where found | Why it exists |
|---------|-------------|---------------|
| **Family dispatcher** (`createDispatcher({param, routes, entry})`) | `serverless/dispatch.js`, used by all 6 `api/**` files | Serve 18 URLs with 6 functions under the Hobby 12-function budget; per-request `import()` for fault isolation and cold-start cost |
| **Shared serve-module for API parity** | `backend/utils/forecastServe.js` (forecasts), `backend/utils/chatService.js` (chat) | The Express deployment and the Vercel deployment must behave identically; the header comments record that they previously did not |
| **Policy-as-data** | `backend/alerts/policy.js` (levels, thresholds, auto-publish ceiling, duty officers) | Threshold changes are reviewable config, and every alert records the `policy_version` that produced it |
| **Append-only event log + derived state** | `backend/alerts/store.js` (`alertFromDocument()` replays `events`) | Full review history (incl. rejections) survives; no deletes, so the archive is usable as ground truth |
| **Singleton cached store + in-memory fallback** | `backend/forecastStore.js` (`getForecastStore`/`resetForecastStore`), `backend/alerts/store.js` | One Firestore handle per process; graceful degradation when Firestore is unprovisioned/offline |
| **Guard middleware (serverless rate limiting)** | `backend/middleware/serverlessGuard.js`, called by every `serverless/**` handler | Express limiters never run on Vercel; a missing guard fails a test (`__tests__/api/serverlessGuard.test.js`) |
| **Multi-tier LLM cascade + circuit breakers + TTL/LRU cache** | `backend/utils/ai_fallback_engine.js` (6 tiers: Gemini → Gemini backup → OpenRouter → Groq → HuggingFace → deterministic heuristic) | Free-tier quota/429 resilience; every response is stamped with `provider_source` |
| **TTL in-memory cache for a third-party API** | `backend/utils/openMeteo.js` (single, mini and **batch** entry points) | One upstream call for all 64 districts instead of 64; rate limits |
| **Graceful degradation chain (3 levels)** | `frontend/src/hooks/useForecasts.ts` → API → committed snapshot → static baseline | The map never blanks out when the store or the API is unavailable |
| **Prerender + content engine** | `frontend/scripts/prerender.mjs`, `scripts/build_content_engine.mjs`, `frontend/src/content/site-routes.json` | SEO/performance and 74 generated pages (methodology per hazard, outlook per district) that cannot drift from the data |
| **Artifact-derived observability** | `scripts/build_freshness_artifact.mjs`, `data/site-health/latest.json`, `frontend/src/pages/StatusPage.tsx` | "Nothing new always-on": a static status page built from committed files plus a 30-minute probe |
| **Design tokens + a waived baseline gate** | `packages/design-system/src/*`, `frontend/src/design-system/*`, `docs/design/impeccable-baseline.json`, `scripts/check-design-quality.mjs` | One token source for web/mobile; the design gate only ever shrinks |
| **Security policy in one place + parity test** | `backend/security/csp.js` → helmet in `backend/server.js`, `vercel.json`, `frontend/vercel.json`; `__tests__/securityHeadersParity.test.js` | The CSP previously existed in three drifting editions |
| **Model-artifact denial** | `backend/server.js` (404 for `/Models`, `*.tflite`, `*.h5`, …), `__tests__/modelArtifactsNotServed.test.js` | Publication policy: artifacts are never downloadable |

### 5) Known Architectural Risks

- **Two HTTP stacks, one domain.** Every new endpoint must be wired twice (Express route **and**
  serverless handler) and must call both limiters. Parity is maintained by convention plus tests
  (`__tests__/api/serverlessGuard.test.js`, `__tests__/api/serverlessRouting.test.js`);
  `serverless/dispatch.js` also documents that a JSON 404 (not the edge's HTML) is what a
  mis-wired frontend call receives.
- **Per-instance rate limiting only on Vercel.** `serverlessGuard.js` states the limit is
  per-instance (`limit × instances`); a shared counter (Upstash/Redis) is recorded as an owner
  action in a file that does not exist in this tree (`docs/ops/owner-actions.md`).
- **Firestore accessed with the client SDK on the server** (`backend/db.js` uses `firebase/firestore`,
  while writes use `firebase-admin`). Reads therefore depend on Firestore rules
  (`allow get, list: if true` for `forecasts`) rather than on a service identity.
- **Committed artifacts as production data.** The site can serve hours-old snapshot JSON
  (`frontend/public/data/forecasts-latest.json`) even when the store is unreachable; correctness
  depends on the scheduled workflows running and on CI comparing the committed content index.
- **Alert thresholds are placeholders.** `backend/alerts/policy.js` states that with
  `model_severity` saturating at 1.0 nearly every district lands at `WATCH`, and that the owner
  must set real thresholds before external alerting.
- **A large amount of dead or dangling intent.** `backend/middleware/securityHeaders.js` is
  CommonJS (`require('helmet')`) in an ESM repo and is imported by nothing; 62 paths referenced
  from tracked source/doc files do not exist anywhere in the tree (see `CONCERNS.md`).

## Extended Sections (Optional)

### Startup / initialisation order (self-host)

1. `dotenv.config()` then the **`assertEnvironment()` IIFE** logs warnings (missing `GEMINI_API_KEY`,
   VAPID keys) and errors (missing `BACKEND_API_KEY`; missing `FRONTEND_ORIGIN` in production) —
   non-fatal so local dev still boots (`backend/server.js`).
2. `helmet` (CSP from `cspDirectivesFromString()`; enforcing in production unless `CSP_ENFORCE` overrides),
   `requestId` logging middleware, CORS allowlist, `express.json({limit:'10mb'})`,
   baseline security headers, `/.well-known/security.txt`, `/health`, model-artifact 404s.
3. API routers with layered limiters (`/api` → per-route buckets; `/api/chat` and `/api/grounding`
   additionally get `attachFirebaseAuthUser` + `dynamicAiLimiter`).
4. `/metrics` refreshes the forecast-age gauge **on scrape** (`refreshForecastAgeGauge()`),
   then static `frontend/dist`, then the SPA fallback (which re-404s model file extensions).
5. Port binding happens only when the module is the process entry point; `freePort()` kills stale
   PIDs holding the port and `startServer()` retries `EADDRINUSE` five times.

### Async / event topology

- **WebSocket:** `backend/routes/liveVoice.js` exports `liveVoiceRouter` and
  `setupLiveVoiceWebSocket(server)`; the server attaches it to the HTTP server at bind time.
- **Scheduled:** two cron workflows (`daily_advisory_ingest.yml` 05:30 UTC, `site-health.yml`
  every 30 min) plus dispatch-only workflows (`Firebase-Store-Verify.yml`, `verify-secrets.yml`,
  `app-releases.yml` on `v*` tags).
- **Concurrency control:** `concurrency:` groups on every workflow (`cancel-in-progress: false`
  for the ingest job so a run is never cancelled mid-write).
- **Push:** web-push subscriptions (`backend/routes/push.js`) and Expo notifications
  (`apps/mobile/src/lib/notifications/*`); no queue/broker — everything is request- or cron-driven.

### Failure modes and resilience posture

| Failure | Behaviour | Evidence |
|---------|-----------|----------|
| Forecast store unavailable | Snapshot JSON → static baseline on the client; on the server the freshness gauge is **hidden** (series absent) rather than reported as 0 | `frontend/src/hooks/useForecasts.ts`, `backend/utils/forecastFreshness.js` |
| AI provider 429/quota | Circuit breaker trips that provider for 45 s and the cascade falls through to the next tier, ultimately a deterministic heuristic | `backend/utils/ai_fallback_engine.js` |
| Firestore write exceeds limits | `persistForecasts()` throws before any write (transaction, 500-operation ceiling) | `backend/forecastPersistence.js` |
| Serverless handler throws | `createDispatcher` answers JSON 500 with `Cache-Control: no-store` | `serverless/dispatch.js` |
| `BACKEND_API_KEY` unset | Ingest and privileged routes return 503 (fail-closed) | `backend/utils/apiKeyAuth.js` |
| Frontend chunk/render error | Root `ErrorBoundary` + per-route `Suspense` fallback (`InfinityLoader`) | `frontend/src/App.tsx`, `frontend/src/components/ErrorBoundary.tsx` |
