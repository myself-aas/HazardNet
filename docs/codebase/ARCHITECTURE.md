# Architecture

> Generated by the `acquire-codebase-knowledge` skill (2026-09-11). Every claim is traceable to the listed evidence.

## Core Sections (Required)

### 1) Architectural Style

- Primary style: **Layered client–server monorepo with a dual deployment topology** — an Express server (local/self-host) mirrors a set of Vercel serverless functions (production), both fronted by a React SPA.
- Why this classification: `backend/server.js` mounts middleware → routes → services/utils in strict layers; `api/*.js` handlers reuse the same `backend/` modules serverlessly; ADR 0003 states "Vercel is the primary deployment target … the Node server is the local development and self-hosting runtime."
- Primary constraints:
  1. **Three backend platforms coexist** (Supabase = identity/relational system of record + forecast store *implementation*; Firebase applet Firestore = forecast store *default*; Firebase RTDB = presence) — explicitly tolerated legacy per ADR 0001/0002. Since 2026-09-12 the forecast store is a single switchable layer (`backend/forecastStore.js`, `FORECAST_STORE` env), so the Firestore→Supabase cutover (ADR 0002) is a config flip, not a code change.
  2. **Offline-capable, low-bandwidth field use** drives the service worker, tile caching, PDF export, and route-level code splitting (FE-01).
  3. **Fail-closed security posture** after the 2026-08-28 audit program (rate limits, timing-safe keys, CSP, default-deny Firestore rules).

### 2) System Flow

Weekly forecast pipeline (the system's backbone):

```text
GitHub Actions (Sun 02:00 UTC)
  -> Kaggle notebook (HDX COD-AB ADM3 x507 locations, GEE Sentinel-1/2 + ERA5-Land, Open-Meteo deterministic forecast)
  -> TFLite/TF inference per district (64 districts × 8 hazards × 2 horizons)
  -> CSV -> POST /api/v1/forecasts/update (backend/server.js) or api/ingest.js (chunks)
  -> forecastStore.js  ── FORECAST_STORE: 'firestore' (default, backend/db.js) | 'supabase' (pg pool, ADR 0002)
  -> GET /api/v1/forecasts[/bulk] serves district/division aggregates
```

Live inference + advisory request flow (user-facing):

```text
Browser SPA (frontend/src/App.tsx)
  -> fetch('/api/predict') [hooks/usePrediction.ts, Dashboard.tsx:310]
  -> apiLimiter -> validateTensor (zod, backend/middleware/validation.js)
  -> backend/inference.js (TFJS: temperature-scaled softmax over 8 hazard classes)
  -> predictionCache (LRU, utils/predictionCache.js) -> JSON response
  -> (advisory) fetch('/api/advisory') -> services/advisoryAgent.js (Gemini 2.5 Flash)
       or /api/chat/query -> rag_pipeline search -> utils/ai_fallback_engine.js cascade
```

Steps, with evidence:

1. **Data acquisition**: Kaggle notebook pulls satellite/climate inputs (`kaggle_notebooks/.../hazardnet-auto-forecast-pipeline.ipynb`; Open-Meteo URL confirmed inside the notebook) and its **507-unit ADM3 location matrix from the attached HDX COD-AB dataset** (`load_hdx_adm3_boundaries`, ADR 0005 — FAO GAUL decommissioned, GEE has no ADM3). Optional fail-soft byproducts (ADR 0006 8b): the OSM/Geofabrik exposure overlay (`hazardnet_adm3_exposure.csv`), the 507-unit location matrix (`hazardnet_adm3_locations.csv`), and the hazard+exposure `hazardnet_adm3_latest.geojson` — all attached to the weekly GitHub Release and consumed by the self-host PostGIS/tiles module (`scripts/db/003_*.sql`, `scripts/tiles/`).
2. **Ingest + storage**: CSV/multipart → `backend/routes/forecasts.js` POST `/update` (per-row horizon/hazard/severity/confidence validation) or zod-validated chunk JSON → `api/ingest.js`; both write via `backend/forecastStore.js` — the single forecast persistence layer (ADR 0002), which selects Firestore (`backend/db.js`, default) or Supabase Postgres (`pg`, `FORECAST_STORE=supabase`) and guarantees byte-identical API row shapes across the flip.
3. **Serving**: GET `/`, `/bulk`, and `/history` (added 2026-09-12, backlog 6) on `backend/routes/forecasts.js` read through the same store — latest-per-district for the horizon, or the accumulated history by `from`/`to` prediction_date window (optional `horizon`/`district_id` filters, `format=csv` archive export; default 30 days, max 90) via `getForecastHistory()` on both implementations.
4. **On-demand inference**: `frontend/src/pages/Dashboard.tsx` posts a 15-channel tensor payload to `/api/predict`; `backend/inference.js` loads class labels from `Models/labels.json`, runs TFJS, applies temperature scaling, returns probabilities + severity. **Pre-computed forecasts**: `frontend/src/hooks/useForecasts.ts` (`useLiveDistricts`) fetches `GET /api/v1/forecasts/bulk` (TanStack Query, 30-min stale time) and overlays live severity/hazard onto the static `ALL_64_DISTRICTS` baseline in `LiveMapView` (10/20/30-day horizon toggle + live-status chip; the 507 ADM3 rows are rolled up to parent districts by `rollupAdm3ToDistricts` — ADR 0006 8d — so the overlay keeps full 64-district coverage) and `NationalOverview` — falling back to the static baseline when the API is unreachable (offline posture).
5. **AI advisory/chat**: `/api/chat/query` (`backend/routes/chat.js`) sanitizes input (3,000-char cap, history truncation), runs RAG retrieval (`rag_pipeline/index.js` over `agent_knowledge_base.json` + district baselines), then generates via the 6-tier fallback engine (`backend/utils/ai_fallback_engine.js`).
6. **Notification loop**: browser subscribes via `/api/push/subscribe` (VAPID), backend broadcasts through `/api/push/send` (web-push); `useHazardNotifications` hook triggers alerts per user's home district.
7. **Observability (freshness SLO)**: `GET /metrics` (Node server) refreshes the `hazardnet_forecast_age_hours` gauge on every scrape via `backend/utils/forecastFreshness.js` — a 60s-cached `getLatestPredictionDate()` probe on the forecast store (both implementations) — and serves the full prom-client set; the stateless Vercel counterpart `GET /api/metrics` computes the same gauge live per invocation (503 when the store is unreachable). Absent series = nothing ingested or store unreadable (alert rules in `monitoring/alerts.yml`; dashboard in `monitoring/grafana-dashboard.json`).

### 4) Reused Patterns

| Pattern | Where found | Why it exists |
|---------|-------------|---------------|
| **Fail-closed API-key gate** (timing-safe Bearer verify, 503 when key unset) | `backend/utils/apiKeyAuth.js`, used in `routes/forecasts.js`, `routes/push.js`, `api/forecasts.js`, `api/ingest.js` | SEC-06: authenticated endpoints must never silently open when misconfigured |
| **Circuit breaker + provider cascade** | `backend/utils/ai_fallback_engine.js` (5 breakers, 45 s cooldown, 6 tiers ending in deterministic heuristics) | AI availability under quota/rate limits ("bulletproof multi-tier fallback") |
| **In-memory TTL/LRU caches** | `ai_fallback_engine.js` (10-min advisory cache), `backend/utils/predictionCache.js`, service-worker tile cache | Latency + cost control for repeated district predictions |
| **Graceful-degradation stub via Proxy** | `frontend/src/lib/supabase.ts` (`createMockSupabaseClient`) | App must boot and render when Supabase env is unconfigured |
| **Lazy route chunks** | `frontend/src/App.tsx` (all pages `lazy()` except auth screens) | FE-01: small initial shell on low-bandwidth networks; bundle budget enforced by `scripts/check-bundle.mjs` |
| **Backend-resolver adapter** | `backend/tfjs.js` (single cached TF instance; prefers native, falls back to CPU) | ML-01: optional native speed without hard dependency |
| **Identity-aware rate limiting** | `backend/middleware/supabaseAuth.js` (authed 60/min vs anonymous 10/min on AI routes) | Ties expensive AI calls to real identities while keeping the public demo usable |
| **Generated-artifact provenance** | `Models/VERSION.json` (sha256 per artifact), `scripts/gen-model-version.mjs`, RAG freshness gate | Model/knowledge-base integrity for reproducibility (IEEE TGRS alignment per README) |
| **Env-driven config with loud startup assertions** | `backend/server.js` `assertEnvironment()`, `frontend/src/lib/config.ts` | Fail loudly on misconfig instead of runtime surprises |

### 5) Known Architectural Risks

- **Split-brain forecast storage (reduced 2026-09-12, ops flip pending)**: both forecast implementations now sit behind the single `backend/forecastStore.js` layer (`FORECAST_STORE` env; ADR 0002 expand phase complete — schema + migration script + 12-test parity suite). Residual risk until the credentials-blocked flip: two code paths to keep in parity; new features must target the store interface, never `backend/db.js` directly.
- **Dual deployment surfaces can drift**: `backend/server.js` and `api/*.js` duplicate ingest behavior (CSV vs chunk JSON). *(The second half of this risk — two overlapping Sunday pipelines — was resolved 2026-09-12: `weekly_forecast.yml` repaired and the broken legacy `weekly_hazardnet.yml` retired per ADR 0004.)* Impact: the remaining duplicate is the CSV-vs-chunk ingest pair.
- **Very large UI components**: `LiveMapView.tsx` 130 KB, `DistrictDetailPage.tsx` 104 KB, `Dashboard.tsx` 66 KB (scan "Top 10 largest files"). The re-audit notes "LiveMapView decomposition (first slice done)". Impact: fragile, hard-to-test units; high-churn hotspots.
- **Serverless × in-memory state**: advisory cache, prediction cache, and circuit-breaker state are per-instance memory; on Vercel each invocation may be a fresh instance, largely defeating them (works as designed on the self-host Node server).
- **Frontend vs backend forecast data sources** *(resolved 2026-09-12)*: the frontend previously rendered only the static `ALL_64_DISTRICTS` baseline and never called the forecast API. It now consumes `GET /api/v1/forecasts/bulk` via `useLiveDistricts` (static baseline as offline fallback); direct Firestore reads from the browser remain absent (by design — REST only).

## Extended Sections (Optional)

### Initialization order (backend)

`dotenv.config()` → `assertEnvironment()` (BACKEND_API_KEY problem; GEMINI/VAPID/FRONTEND_ORIGIN warnings) → `trust proxy 1` → helmet CSP (Report-Only unless `CSP_ENFORCE=true`) → requestId → CORS allowlist (`FRONTEND_ORIGIN`, permissive legacy fallback) → JSON body limit 10 MB → `/health` (includes model version handshake) → model-artifact 404 guard → `/api` global limiter → route mounts (chat/agent get `attachSupabaseUser + dynamicAiLimiter`; predict gets tighter `predictLimiter`) → `/metrics` → static `frontend/dist` + SPA fallback (blocking `/Models`, `*.tflite` etc.) → listen. Evidence: `backend/server.js`.

### Failure-mode posture

- AI tier cascade ends in a **zero-latency deterministic heuristic** (`ai_fallback_engine.js` → `generateDeterministicHeuristicAdvisory`), so advisory generation never hard-fails.
- Ingest endpoints clean up uploaded temp files on validation failure (`routes/forecasts.js`).
- SPA fallback returns 503 with a friendly message while the frontend build is missing.
- `frontend/src/components/ErrorBoundary.tsx` wraps the app (`App.tsx`).
