# Architecture

Generated by the `acquire-codebase-knowledge` workflow on **2026-10-09** against commit
`3a1af69c0e8ee1f3b5edea79764970aa2cc7902d`. Every statement below is read off a file in the
tree; design intent quoted from comments is attributed to that file. Supersedes the 2026-10-02

layer, the historical-dataset ingestion and the two new scheduled pipelines.

## Core Sections (Required)

### 1) Architectural Style

- **Primary style: build-time-published snapshots, served by two interchangeable HTTP runtimes,
  over a monorepo with a shared contract + design core.** Not layered-clean-architecture, not
  event-driven: there is no queue, no broker and no long-running worker anywhere in the tree
  (scan §CONTAINERS & ORCHESTRATION: none; no `kafka`/`amqp`/`sqs`/`pubsub` dependency in any
  manifest).
- **Why this classification:**
  1. The authoritative data path **commits its own output to git**. `daily_advisory_ingest.yml`
     fetches a CSV, rebuilds four artifacts and `git push`es them, then triggers a deploy.
     The frontend's primary read is a static file: `FORECAST_SNAPSHOT_URL = '/data/forecasts-latest.json'`
     (`frontend/src/lib/forecasts.ts:419`, fetched with `cache: 'no-store'` at lines 487/505).
  2. Scheduling is **the CI platform's**, not the app's — **four** cron-triggered workflows
     (`daily_advisory_ingest` 05:30 UTC, `live-wind-update` `10 */6 * * *`,
     `site-health` `*/30 * * * *`, `secret-rotation-audit` `15 7 1 * *`), one tag-triggered
     release workflow, and three that are dispatch-only.
  3. The same API surface is implemented twice — Express (`backend/routes/**`) and Vercel
     functions (`serverless/**`) — and parity is maintained by **sharing the logic modules**, not
     by generating one from the other.
- **Primary constraints (all three shape the design visibly):**
  - **Vercel Hobby: ≤12 Serverless Functions.** The entire `api/` ↔ `serverless/` split exists
     for this. Measured **6/12** (`npm run check:functions`).
  - **`docs/PUBLICATION_POLICY.md` is binding:** model code, dataset collection, training,
     benchmarking and severity derivation are research-private. Inference therefore lives in a
     Kaggle notebook **outside this repository**; no ML framework appears in any manifest.
  - **Low-end Android on 2G/3G is the design target, not a fallback** (`PRODUCT.md` §Operating
     Context). Enforced mechanically: 800 KiB gzip per chunk / 1,600 KiB total
     (`scripts/check-bundle.mjs:13`), route-level `lazy()` for every page, a 50 KiB Bangla
     webfont budget (`scripts/check-font-payload.mjs`).

### 2) System Flow

**Flow A — the published-number path (the product's spine)**

```text
Kaggle notebook (out of repo)
  -> .github/workflows/daily_advisory_ingest.yml  (cron 05:30 UTC)
     -> scripts/fetch_kaggle_advisory.mjs        --wait-minutes 12 --max-age-hours 36
                                                  exit 0 fresh / 2 unchanged-or-stale / 1 failed
     -> scripts/process_advisory_ingest.mjs      validate -> map 22 advisory columns -> write
        backend/data/forecasts/{hazardnet_forecasts_latest.csv,.json,manifest.json}
     -> scripts/rehearse_alert_engine.mjs        -> /tmp/advisory-ingest/alert-run.json
     -> scripts/build_alert_snapshot.mjs         -> frontend/public/data/alerts-latest.json
     -> scripts/build_freshness_artifact.mjs     -> frontend/public/data/freshness.json
  -> node --test __tests__/advisoryPipeline.test.js
  -> git commit + git push (backend/data/forecasts/, forecasts-latest.json,
                            alerts-latest.json, freshness.json)
  -> npx vercel deploy --prod   (only if artifacts changed AND VERCEL_TOKEN is set)
  -> scripts/notify_ops.mjs -> Slack #hazardnet-ops   (if: always())
```

**Flow B — a browser read**

```text
frontend/src/main.tsx -> App.tsx (76 <Route>, all pages lazy())
  -> page/hook (e.g. useForecasts, useKaggleAdvisories)
     -> frontend/src/lib/forecasts.ts
          primary:  GET /data/forecasts-latest.json   (committed snapshot, cache: 'no-store')
          alternate: GET /api/v1/forecasts/metadata + /api/v1/forecasts/bulk?horizon=7_days
     -> @hazardnet/core contracts (Zod) validate/shape the row
     -> @hazardnet/design-system (apple.ts) resolves every colour/type/radius/motion value
  -> TanStack Query cache -> React render -> four-state surface (loading/empty/error+retry/success)
```

**Flow C — a serverless API request**

```text
GET /api/v1/forecasts/bulk
  -> Vercel matches api/v1/forecasts/[action].js        (one of 6 functions)
  -> serverless/dispatch.js: routeSegment(req,'action',table)
       path is the source of truth; ?action= is the fallback for direct invocation;
       BOTH are stripped before the handler runs, so a routing artefact can never be
       mistaken for a user-supplied query parameter
  -> guardRequest(...)                                   backend/middleware/serverlessGuard.js
       per-instance, cost-bucketed rate limits + metering (an unrouted 404 is metered as a read)
  -> () => import('../../../serverless/v1/forecasts/bulk.js')   (per-request, literal specifier)
  -> backend/utils/forecastServe.js                      the SAME module Express uses
  -> backend/forecastStore.js -> Firestore, falling back to the committed JSON snapshot
  -> JSON response; 5xx text is replaced by backend/utils/clientError.js
```

Six steps, all file-backed: match → route → guard → lazy-load → shared serve module → store.

### 4) Reused Patterns

| Pattern | Where found | Why it exists |
|---------|-------------|---------------|
| **Dispatcher / front-controller** | `serverless/dispatch.js` + all six `api/**` entry points | The 12-function budget: one function per URL *family*, dispatching to handlers Vercel never scans |
| **Per-request lazy import with literal specifiers** | `api/[endpoint].js`, `api/v1/[resource].js`, `api/v1/alerts/[action].js`, `api/v1/forecasts/[action].js`, `api/chat/[action].js` | Two reasons, both stated in `dispatch.js`: **fault isolation** (a module-level throw in one handler's import graph must not fail the family) and **cold start** (a lambda serving five endpoints should not pay for five import graphs) |
| **Shared-module parity** | `backend/utils/forecastServe.js`, `backend/utils/chatService.js`, `backend/middleware/serverlessGuard.js` (imported by `serverless/dispatch.js`) | Two runtimes, one behaviour — parity by construction rather than by test |
| **Provider cascade + circuit breaker** | `backend/utils/ai_fallback_engine.js:466-512` — `cascadeProviders` array, per-provider timeout, `circuitBreakers` with `TRIP_COOLDOWN_MS = 45_000`, 429 trips the breaker and falls through | Free-tier LLM quotas are the norm here; a hung or quota-exhausted upstream must not eat the whole request |
| **Deterministic fallback** | `backend/utils/ai_fallback_engine.js` → heuristic engine; `backend/server.js:44` warns when `GEMINI_API_KEY` is unset rather than failing | The advisory surface must render with no AI provider at all |
| **Singleton with a reset hook** | `backend/forecastStore.js` (`cachedStore`, `getForecastStore()`, `resetForecastStore()`) | One store per process, testable |
| **Ratchet / frozen-baseline gate** | `data/design/*.json` (7 ledgers) + `scripts/check-{token-compliance,css-important,svg-tokens,design-residue,contrast}.mjs`; `__tests__/iconFamily.test.js:195` `BASELINE_IMPORTERS = 61` | Debt is enumerated, frozen and only allowed to shrink. Measured: MaterialIcon importers are now **54** (−7 from the 61 baseline) |
| **Fail-closed on missing config** | `backend/utils/apiKeyAuth.js` (503 when `BACKEND_API_KEY` unset), `backend/middleware/cors.js` (production rejects cross-origin when `FRONTEND_ORIGIN` unset) | A misconfiguration must stop the request, not silently widen access |
| **Startup assertion (non-fatal)** | `backend/server.js:36-63` — `problems[]` vs `warnings[]`, logged before the app listens | Loud early signals for misconfig while local dev still boots |
| **Four-state surface** | `data/design/four-state-baseline.json` — one entry per file in `frontend/src/pages`, four states each (loading / empty / error+retry / success) | "Absent is reported as absent" (`PRODUCT.md` principle 2) |
| **Client-safe error boundary** | `backend/utils/clientError.js` — 4xx messages pass through, **5xx always generic** + server-side stack log | Written after a 2026-09-17 live audit found raw driver text reaching clients |
| **Artifact self-description** | `frontend/public/data/freshness.json` (`schema`, `built_at`, `generated_by`, `what_this_is`, per-source `state`/`reason`/`age_hours`) | Every published number carries its provenance (`PRODUCT.md` principle 1) |
| **Root ErrorBoundary + `lazy()`** | `frontend/src/App.tsx`, `frontend/src/components/ErrorBoundary.tsx` | Route-level code splitting (FE-01) and containment of a failed chunk |

### 5) Known Architectural Risks

- **The published data path is stale and the architecture has no way to notice from inside.**
  `backend/data/forecasts/manifest.json` says `prediction_date: 2026-09-16`, `row_count: 74`
  (the contract in `CLAIMS.md` CLM-005 is **128** = 64 districts × 2 horizons). The freshness
  artifact measures it: `forecast_ingest` is `stale` — *"prediction_date 2026-09-16 is 572.2 h
  old (SLO 192 h)"* — and `overall.state` is `"failing"`. Root cause is upstream and owner-side
  (Kaggle has not published since 2026-09-29; `docs/ops/owner-actions.md` Action 11).
  **Impact:** the site serves 24-day-old outlooks as "latest" while correctly labelling them stale.
- **Observability of the live site is currently blind, not red.** `data/site-health/latest.json`
  (`ran_at: 2026-10-09T20:09:56Z`) reports `outcome: "fail"` with **all seven checks failing**.
  Measured in `docs/audits/2026-10-09-cloudflare-403-origin-probe.md`: every probe request
  returns `HTTP 403` with `server: cloudflare` and `cf-mitigated: challenge` — no origin ever
  answers. **Impact:** the probe cannot distinguish an outage from a bot challenge, so it has
  committed 56 consecutive failure artifacts; the workflow side is implemented (`x-hazardnet-probe`
  header + `edge_challenged` field) and the remainder is owner-side (Action 18).
- **Two deploy paths, and the code disagrees with reality about which one is live.**
  `vercel.json` + `frontend/vercel.json` describe the Vercel path; `firebase.json` +
  `.firebaserc` describe Firebase Hosting. `docs/ops/owner-actions.md` Action 16 recorded **41
  tracked files** treating `https://www.hazardnet.live` as canonical on 2026-10-04; **measured
  today it is 61** (`git grep -l 'www\.hazardnet\.live'`) — the coupling grew by 20 files in five
  days. `frontend/scripts/prerender.mjs` **fails the build** on any other origin —
  and `www.hazardnet.live` **now resolves and serves the site through Cloudflare**, which closes
  the NXDOMAIN premise of Action 16 as of 2026-10-10; `hazardnet.live` answered from Firebase
  Hosting when measured on 2026-10-04 (Actions 16/17, decision 2026-10-04: `www` stays canonical).
  **Impact:** the sitemap URLs are reachable again, but which platform publishes the live build is
  still unresolved (Action 17), so the security-header probe still reads a host this repository
  cannot prove it deploys to.
- **Rate limiting is per-instance.** `backend/middleware/serverlessGuard.js` states the ceiling
  is `limit × instances`. **Impact:** the effective API limit scales with warm lambdas; a shared
  counter is owner Action 8.
- **Two HTTP stacks for one domain.** An endpoint added to only one runtime is reachable in one
  deployment and 404 in the other. **Impact:** mitigated by `forecastServe.js`/`chatService.js`
  sharing and by `__tests__/api/serverlessRouting.test.js` + `securityHeadersParity.test.js`,
  but there is no route-inventory test asserting both runtimes expose the same path set.
- **One component carries the map.** `frontend/src/components/LiveMapView.tsx` is **2,658 lines**
  and the 4th-highest-churn source file (21 touches in 90 days). **Impact:** the highest-risk
  single file in the tree; also the file that historically carried 79 raw hex literals through a
  green gate (`data/design/hex-baseline.json`).
- **Build-time compatibility shims are load-bearing.** `frontend/vite.config.ts` carries
  `leafletGlobalShim()` because Vite 8/Rolldown lazily initialises the CommonJS `leaflet` export,
  which made pre-ESM plugins throw `ReferenceError: L is not defined` and white-screen every
  production page. **Impact:** a Vite or plugin upgrade can silently re-break production; only the
  E2E job (which builds first) catches it.

## Extended Sections (Optional)

### Vercel serverless surface (the 12-function budget)

**The constraint.** The Vercel Hobby plan allows **at most 12 Serverless Functions per
deployment**, and every file under `api/` is one function. This repository serves more public
URLs than that (`serverless/dispatch.js` header says 18). A file per URL does not fit.

**The design.** `api/` holds one entry point per URL *family*; each is a thin
`createDispatcher({ param, entry, routes })` call. The handlers live in `serverless/`, a
directory Vercel never scans for functions (only `api/` is).

**Measured: 6 of 12 functions deployed, 6 left on the budget** (`npm run check:functions`):

| # | Function file | Family | Dispatches to |
|---|---|---|---|
| 1 | `api/[endpoint].js` | top-level | `serverless/{forecasts,historical,ingest,metrics,predict}.js` |
| 2 | `api/chat/[action].js` | chat | `serverless/chat/query.js` (+ `sample-questions.js`) |
| 3 | `api/v1/[resource].js` | v1 resources | `serverless/v1/{alerts/index,historical,weather,telemetry}.js` |
| 4 | `api/v1/alerts/[action].js` | alerts actions | `serverless/v1/alerts/{policy,review,run}.js` (+ `evidence-card.js`) |
| 5 | `api/v1/forecasts/[action].js` | forecast actions | `serverless/v1/forecasts/{bulk,history,metadata}.js` |
| 6 | `api/v1/weather/batch.js` | static sibling | itself (static wins over a dynamic segment) |

**Routing contract** (verified against the Vercel CLI's local build/dev emulation, recorded in
`serverless/dispatch.js`):

- `api/v1/alerts/[action].js` matches `/api/v1/alerts/policy`; Vercel passes the matched segment
  as `?action=policy` **appended to the original query string** while leaving `req.url` untouched.
- **Static siblings win** over a dynamic segment: `/api/v1/alerts` reaches
  `serverless/v1/alerts/index.js`, `/api/v1/weather/batch` reaches the static
  `api/v1/weather/batch.js`.
- **Only one segment is matched**; a deeper path is not a route.
- The **path is the source of truth** for the segment; the query parameter is the fallback (for a
  direct invocation such as a unit test). **Both are stripped from the request before the handler
  runs**, so a handler can never mistake a routing artefact for a user-supplied `?action=`.
  The stripping mutates the request in place — safe because Vercel hands each invocation its own
  request object; a test harness that reuses one object must rebuild it per call.
- An unmatched path gets a **JSON 404**, not the edge's HTML 404, metered with the `read` bucket
  (an unrouted path still costs an invocation, so it is not left unmetered — SEC-07).

**The gate.** `scripts/check-vercel-functions.mjs` (`HOBBY_FUNCTION_LIMIT = 12`,
`HEADROOM_WARNING = 2`) runs in CI (`ci.yml` step *"Vercel function budget (Hobby: 12)"*) and
exits 1 over budget. `__tests__/api/serverlessRouting.test.js` and
`__tests__/api/serverlessGuard.test.js` exercise the contract and assert a new endpoint cannot be
added without the guard.

**Adding an endpoint:** put the handler in `serverless/`, add one entry to the relevant family's
`routes` table with a **literal** `() => import('…')` specifier (so the bundler can trace it),
then run `npm run check:functions`. Only a new URL *family* consumes budget.

### Startup / initialisation order (self-host)

`backend/server.js`, in order: `dotenv.config()` → `assertEnvironment()` IIFE (problems/warnings)
→ `express()` → `app.disable('x-powered-by')` → `app.set('trust proxy', 1)` (rate limiters need
the real client IP behind one proxy hop) → `helmet({frameguard: deny, hsts 2 y + preload,
contentSecurityPolicy: {reportOnly: !cspEnforce, directives: cspDirectivesFromString()}})` →
`requestId` → `corsMiddleware()` → `express.json({limit:'10mb'})` → the manual header middleware
(including the RFC 9727 `Link: rel="api-catalog"` and the `WWW-Authenticate: Bearer
resource_metadata=…` advertised on **every** response) → `.well-known` endpoints → routers →
`/health` → `/metrics` → the SPA catch-all `app.get('*')`.

`cspEnforce` resolves as: `CSP_ENFORCE` if defined, else `NODE_ENV === 'production' ||
VERCEL_ENV === 'production'` (ADR 0003 — enforcing in production, Report-Only in development).

### Failure modes and resilience posture

| Failure | Posture | Evidence |
|---|---|---|
| LLM provider down / quota-exhausted | Per-provider timeout, circuit breaker with 45 s cooldown, cascade to the next provider, final deterministic heuristic fallback | `backend/utils/ai_fallback_engine.js:25,39-109,466-512` |
| Firestore unprovisioned / offline / 0 records | Automatic fallback to the committed static snapshot; `firestoreAvailable` flag re-probes | `backend/forecastStore.js:172-183,211-406` |
| `BACKEND_API_KEY` unset | **Fail closed**: privileged endpoints return 503 | `backend/utils/apiKeyAuth.js`, `backend/server.js:41` |
| `FRONTEND_ORIGIN` unset in production | **Fail closed**: cross-origin browser requests rejected, not reflected | `backend/middleware/cors.js`, `backend/server.js:50-57` |
| Kaggle CSV stale (>36 h) or unchanged | The **fetch step** fails with the publication age (moved upstream 2026-10-04 so the red names its real cause); a scheduled no-update exits 1, a manual rehearsal stays a successful no-op | `daily_advisory_ingest.yml`, `scripts/validate_advisory_csv.mjs` |
| Leaflet plugin throws in a production build | Build-time `leafletGlobalShim()` pins initialisation order inside the plugin module | `frontend/vite.config.ts:70+` |
| A page chunk fails to load | Root `ErrorBoundary`; per-surface four-state (loading/empty/error+retry/success) | `frontend/src/App.tsx`, `data/design/four-state-baseline.json` |
| A district the run did not cover | Reported as absent in words, carries `robots: noindex,follow` and no sitemap entry — never rendered as zero | `PRODUCT.md` principle 2, `frontend/scripts/prerender.mjs:629` |
