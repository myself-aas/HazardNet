### 4) Reliability and Failure Behavior

- **Retry / backoff:**

  | Where | Policy | Evidence |
  |---|---|---|
  | `packages/api` client (web + mobile) | `DEFAULT_RETRY_POLICY`: maxRetries 5, base 1 000 ms, factor 2, full jitter, hard cap 1 h; retryable statuses {408, 409, 425, 429, 500, 502, 503, 504} | `packages/api/src/retry.ts` |
  | Kaggle HTTP download | `attempts = 3`, `backoffMs = 20_000`; a 401/403 is **not** retried ("that means the key, not the network") | `scripts/fetch_kaggle_advisory.mjs` |
  | Kaggle fetch round | three methods in order: dataset over HTTP → dataset via CLI → kernel output via CLI; plus `--wait-minutes 12` polling | `scripts/fetch_kaggle_advisory.mjs`, `daily_advisory_ingest.yml` |
  | AI providers | per-provider timeout; circuit breaker with 45 s cooldown; 429 trips and falls through; final deterministic heuristic | `backend/utils/ai_fallback_engine.js` |
  | Analytics beacon | batching, queue cap, **one retry then drop**, `sendBeacon` on unload | `packages/analytics/src/streaming.ts` |
  | Playwright (E2E) | `retries: CI ? 2 : 0` | `playwright.config.ts` |

- **Timeout policy:**

  | Integration | Timeout | Where |
  |---|---|---|
  | Telegram | 8 000 ms default, `TELEGRAM_TIMEOUT_MS` | `backend/alerts/channels/telegram.js` |
  | SMS | 8 000 ms default, `SMS_TIMEOUT_MS`; plus `SMS_MAX_PER_RUN` = 25 and `SMS_DRY_RUN` | `backend/alerts/channels/sms.js` |
  | AI providers | per-provider timeout constant | `backend/utils/ai_fallback_engine.js` |
  | Express body parse | `express.json({ limit: '10mb' })` | `backend/server.js` |
  | CI jobs | `timeout-minutes: 25` (ingest), `15` (security-audit), `10` (pipeline-scripts) | `.github/workflows/*` |
  | Playwright | `timeout: 60_000` per test | `playwright.config.ts` |
  | Kaggle freshness gate | `--max-age-hours 36` at fetch **and** at ingest | `daily_advisory_ingest.yml` |

- **Circuit-breaker / fallback behaviour:**
  - AI: circuit breakers with a 45 s half-open cooldown and a `getSystemStatus()` telemetry
    view per provider.
  - Store: `firestoreAvailable` is a soft breaker — on failure it flips false, serves the
    committed snapshot, and re-probes on later calls.
  - CORS: **fails closed** in production when `FRONTEND_ORIGIN` is unset.
  - API key: **fails closed** with 503 when `BACKEND_API_KEY` is unset.
  - Rate limiting: **per-instance only** on a function host — `serverlessGuard.js` states the effective
    ceiling is `limit × instances`, and that a shared counter (Upstash/Redis) is owner
    Action 8. Buckets by cost, not by route: `read 120/min`, `alerts 60/min`, `ai 20/min`,
    `pipeline 12/min` (**×10** with the pipeline key), `metrics 60/min`.
  - The dependency-free design of `serverlessGuard.js` is deliberate: "a serverless cold start
    should not pay for a Redis client."
  - **Serverless dispatch**: a deleted/broken handler module fails per-route with JSON 500;
    the rest of the family is unaffected (`serverless/dispatch.js:76-82`) — exercised for real
    at HEAD.

### The AI cascade, in order

`backend/utils/ai_fallback_engine.js` builds `cascadeProviders` and walks it:

```text
gemini_primary     Gemini            (GEMINI_API_KEY)
  -> gemini_secondary  Gemini backup (GEMINI_API_KEY_BACKUP)   [also used by liveVoice.js]
  -> openrouter        OpenRouter    (OPENROUTER_API_KEY)  several free slugs, cascading internally
  -> groq              Groq          (GROQ_API_KEY)
  -> huggingface       HuggingFace   (HUGGINGFACE_API_KEY)
  -> deterministic heuristic engine                            [no credential required]
```

Each tier is skipped when its key is absent or when its breaker is tripped. A missing
`GEMINI_API_KEY` is a **warning**, not a problem, at startup precisely because the heuristic
tier exists (`backend/server.js`). A **10-minute** advisory cache sits in front of the whole
cascade, keyed on `district:hazard:round(severity*10):promptHash`, so a repeated advisory need
not spend a provider at all. Grounding (search / Maps) is a separate path —
`backend/utils/gemini_grounding.js` with `detectGroundingIntent`, `executeSearchGrounding`,
`executeMapsGrounding`.

### Region / failover topology notes

There is no multi-region topology in the repository. The failover that exists is
**provider-level and store-level**, not regional: Kaggle HTTP → Kaggle CLI → Kaggle kernel;
five LLM providers → heuristic; Firestore → committed snapshot → (tests only) memory. The
wind-artifact ladder (GFS → ECMWF) was retired with the layer. The hosting question is settled
as of 2026-10-26: **one Cloudflare Pages deployment answers both `hazardnet.live` and
`www.hazardnet.live`** (`docs/ops/deployment.md`), the Vercel configuration is deleted, and
`firebase.json` now carries only the Firestore config (its `hosting` block was retired on
2026-10-26, after measuring that `hazardnet-aas48424.web.app` still served the 2026-09-24
build — `docs/ops/owner-actions.md` Action 22). Every tracked file that treats
`https://www.hazardnet.live` as canonical is therefore pointing at a hostname that serves the
same deployment as the apex.
