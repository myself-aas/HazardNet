### 3) Secrets and Credentials Handling

- Credential sources: environment variables only — backend via `dotenv` (`backend/server.js`, `db.js`), frontend via `import.meta.env` (`VITE_*`); CI/weekly pipelines via GitHub Secrets (`KAGGLE_USERNAME`, `KAGGLE_KEY`, `GEMINI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` — `.github/workflows/weekly_forecast.yml`); production via Vercel project settings (ADR 0003).
- Hardcoding checks: **no secrets committed.** `firebase-applet-config.json` and the literal defaults in `frontend/src/lib/config.ts` are Firebase *public-by-design* client identifiers, explicitly sanctioned by ADR 0001 ("defaults are convenience-only"). Verified: scan found no `.env*` files; `Models/` contains no keys; one benign TODO (`frontend/src/services/firebase.ts:18`).
- Rotation/lifecycle notes: `GEMINI_API_KEY_BACKUP` supports key rotation (tier-2 breaker); `SUPABASE_SERVICE_ROLE_KEY` used by the weekly pipeline for DB writes; `DATABASE_URL` + `SUPABASE_SSL` + `FORECAST_STORE` drive the ADR 0002 forecast-store selection. The required set is documented in **root `.env.example` and `frontend/.env.example`** (added 2026-09-12; closed the CONCERNS gap). The weekly workflow reads `FORECAST_STORE` from the repo variable and `DATABASE_URL` from the `SUPABASE_DB_URL` secret (both no-ops until the cutover flip).

### 4) Reliability and Failure Behavior

- Retry/backoff behavior: **partial** — AI providers have circuit breakers (trip on 429/quota, 45 s cooldown, HALF-OPEN retry) plus a 6-tier cascade ending in a deterministic offline heuristic (`backend/utils/ai_fallback_engine.js`); no generic retry/backoff for Firestore/Supabase/HTTP fetches `[TODO]`.
- Timeout policy: none found at the HTTP-client level for external APIs `[TODO]`; rate limits act as the primary abuse control (express-rate-limit buckets; dynamic AI lanes 60/min authed vs 10/min anonymous).
- Circuit-breaker or fallback behavior: yes for AI (above); TF backend falls back CPU↔native (`backend/tfjs.js`); advisory agent falls back to canned text; Supabase unconfigured → mock client (frontend never crashes); ingest fails closed without `BACKEND_API_KEY`; `FORECAST_STORE=supabase` without `DATABASE_URL` → problems-level startup error (server) and loud per-call errors — never a silent fallback to Firestore; Supabase replace operations run in a transaction (delete+insert) with rollback on failure; the SPA's forecast fetch retries once (TanStack Query) then falls back to the static district baseline.

### 5) Observability for Integrations

- Logging around external calls: tagged console logs in AI fallback engine (provider success/failure, breaker transitions), `[AdvisoryAgent]` fallback warnings, `[inference]` load timing.
- Metrics/tracing coverage: Prometheus counters/histograms via `prom-client` on the Node server (`/metrics`: model load time, request counters, inference latency, **forecast-age gauge** — `backend/metrics.js`, refreshed per scrape by `backend/utils/forecastFreshness.js`); request-id correlation middleware (`backend/middleware/requestId.js`, BE-04). No distributed tracing `[TODO]`.
- Missing visibility gaps (updated 2026-09-12, backlog 5): the former `api/metrics.js` placeholder is replaced — the serverless side now exposes the forecast-age SLO computed live from the store (`503` on store failure so failed scrapes alert); alert rules ship in `monitoring/alerts.yml` (`HazardNetForecastStale` > 192h at weekly cadence, `HazardNetForecastDataMissing` on absence). Still open: no error-*rate* alerting; the Node server's `cache_hit_rate`/`severity_mae`/`prediction_accuracy_per_class` gauges have no writers; provider-failure counts exist in `engineStats` but are not exported to Prometheus.

## Extended Sections (Optional)

### Auth flow summary (user-facing)

Passwordless email-verification sign-up + OAuth providers (`frontend/src/context/AuthContext.tsx`, `lib/oauthProviders.ts`, `docs/user-dashboard.md`): Supabase issues an HS256 access token; the SPA sends it as `Bearer` on AI routes; `attachSupabaseUser` verifies with `SUPABASE_JWT_SECRET` and the dynamic limiter picks the authed lane. Machine-to-machine ingest/push endpoints use a timing-safe `BACKEND_API_KEY` check that fails closed (503) when unset.
