# Coding Conventions

Generated by the `acquire-codebase-knowledge` workflow on **2026-11-17** against commit
`3e7da64` (`main`). The conventions are read off configs and sampled source. Where a rule is
enforced by a gate, the gate is named. Project-level rules for agents and contributors are in
`AGENTS.md` (gates, hard rules) and `docs/agents/impeccable-protocol.md` (design work). This
document does not restate them; it points at them.

### 2) Formatting and Linting

- **Formatter:** Prettier (`.prettierrc`): `printWidth 120`, `singleQuote`, `trailingComma: all`,
  `semi`, `tabWidth 2`, `arrowParens: always`, `endOfLine: lf`. `npm run format` only targets
  `frontend/src/**/*.{ts,tsx}`, `backend/**/*.js` and `api/**/*.js`. **`functions/`, `serverless/`,
  `packages/` and `scripts/` are not in the format glob.** Some files diverge from the config
  (for example `frontend/src/main.tsx:1` uses double quotes).
- **Linter:** ESLint 9 flat config (`eslint.config.js`): `@eslint/js` recommended +
  `typescript-eslint` recommended + `react-hooks` recommended for `frontend/src`.
  - `no-explicit-any`: warn. `no-unused-vars`: warn (`^_` ignored). `no-console`: warn, except
    `warn`/`error`/`info`. It is off for Node scripts, backend and tests. `no-empty`: error, but
    empty catch blocks are allowed.
  - Per-area globals: browser (`frontend/src`), worker (`functions/**`), service worker
    (`frontend/public/**/*.js`), node (backend, scripts, `*.mjs`), jest (tests).
  - Ignored: `dist/`, `node_modules/`, `**/*.cjs`, `docs/`, `Models/`, `.agents/`, `skills/`,
    `references/`, plus `audit_temp/` and `load-tests/` (neither directory exists).
  - **Budget:** `npm run lint:eslint` = `eslint . --max-warnings 600` (ratcheted from 685 on 2026-11-17). Measured 2026-11-17 over
    tracked files: **0 errors, 588 warnings** (12 headroom under 600). Locally, `eslint .` also walks
    untracked folders; on this checkout it crashed with `EPERM` on `.pytest_cache` and reported
    708 errors in untracked `.github/` files, neither of which exists in CI.
- **TypeScript:** `strict: true` in both `frontend/tsconfig.json` and `functions/tsconfig.json`.
  `allowJs` is on and `checkJs` off, so the plain-JS core modules are type-inferred, not
  type-checked (stated in the `frontend/tsconfig.json` comment). `allowImportingTsExtensions`
  is on in the frontend.
- **Design/prose gates** (project-specific, part of "linting" here): `npm run check:device`
  chains 14 checks: tokens, prose dashes, icon glyphs, events summary, `!important`, contrast
  (resolver, CSS, tree), residue, SVG tokens, knowledge base, craft floor. The craft floor
  (`scripts/check-craft-floor.mjs`) enforces the nine mechanical rules restated in `AGENTS.md`.

### 3) Import and Module Conventions

- **ESM everywhere** (`"type": "module"`). Node files import with explicit `.js` extensions
  (`'../serverless/dispatch.js'`). Functions import shared `.js` modules with the extension and
  `.ts` modules without it (`'../../../../backend/edge/response'`).
- **No CommonJS `require` in runtime code.** The one exception found is
  `backend/server.js:186` (`require('child_process')` inside an ESM module). It is a latent bug,
  listed in CONCERNS.md.
- **Path aliases:** `@/*` → `frontend/src/*`; `@hazardnet/{core,api,analytics,design-system}` →
  `packages/*/src` (tsconfig + `jest.config.cjs` `moduleNameMapper`). Packages are consumed as
  **source**, never built. Edge Functions and Node code use **relative paths** into
  `packages/*/src` and `backend/*`, not the aliases.
- **API paths only from `@hazardnet/api`.** A `/api/v1/…` literal elsewhere fails
  `__tests__/apiPathTable.test.js`. Edge handlers call `pathOf()`.
- **Lazy loading:** every page is a `lazy()` import in `App.tsx`. Node dispatchers use literal
  `() => import('…')` specifiers so bundlers can trace them.
- **Export style:** mixed. Pages and many components use `export default` (42 of 64 sampled
  component files); `lib/`, `packages/` and `backend/utils` use named exports. Express routers
  are default exports.
- **Edge-shared modules must be platform-neutral:** "zod + districtRegistry only; no node:*
  built-ins" (`backend/utils/dailyAdvisoryPublic.js` header).

### 4) Error and Logging Conventions

- **Client-facing errors:** 4xx messages written in code pass through. 5xx answers are always
  generic, and the cause goes to the server log (`backend/utils/clientError.js`, 13 call sites).
  Edge handlers follow the same rule by hand: `console.error('[forecasts/bulk] snapshot
  unavailable:', …)` followed by a 503 with a fixed message. The comment explains that the asset
  path must not be echoed.
- **Validation errors:** parse functions return `{ error }` objects rather than throwing
  (`parseBulkQuery` → `if ('error' in parsed) return respond({error}, {status: 400})`).
  Contracts use Zod `safeParse`.
- **Fail closed on missing config:** privileged endpoints answer 503 when `BACKEND_API_KEY` is
  unset (`backend/utils/apiKeyAuth.js`). Production CORS rejects cross-origin requests when
  `FRONTEND_ORIGIN` is unset.
- **Degrade, don't throw, on optional platform features:** Firestore failures trip a breaker and
  fall back to the snapshot (`backend/forecastStore.js`). AI providers cascade
  (`ai_fallback_engine.js`). Missing `ASSETS` → `context.next()` (`functions/[[path]].ts`).
- **Logging:** plain `console.*` with a bracketed module tag: `[forecastStore]`,
  `[AI Fallback Engine]`, `[forecasts/bulk]`. There is no logging library. `prom-client` metrics
  exist on Node only (`backend/metrics.js`).
- **Empty catches are permitted** (`no-empty` with `allowEmptyCatch`) and are used for optional
  features. Because of this, `backend/server.js:186-201` silently swallows a `ReferenceError`.
- **Comments carry incident history.** Many modules open with a long header explaining which
  outage or audit produced them (`frontend/vite.config.ts`, `functions/_middleware.ts`,
  `serverless/dispatch.js`). Several cite `PRODUCT_SPEC §…`, but `docs/PRODUCT_SPEC.md` does not
  exist (`backend/alerts/{assess,digest,policy}.js`).

### 5) Testing Conventions

- Test files sit in `__tests__/` beside the code (`frontend/src/lib/__tests__/`,
  `packages/core/__tests__/`) or in the root `__tests__/`. Suffix `.test.{js,ts,tsx}`; Playwright
  uses `e2e/*.spec.ts`.
- Root suites run under jsdom by default (`jest.config.cjs`) with Babel transforms of everything
  (`transformIgnorePatterns: []`). Pure-Node suites use `node:test` (12 files).
- Fixtures under `__tests__/fixtures/` are **pipeline-written captures** of real upstream
  responses (`scripts/capture_edge_fixtures.mjs`), refreshed by the daily publisher.
- Stores are switched to memory in tests (`FORECAST_STORE_MEMORY`, `ALERT_STORE_MEMORY`), and
  serverless rate limiting can be disabled (`HAZARDNET_DISABLE_SERVERLESS_RATELIMIT`).
- "A suite that genuinely cannot run belongs in a failing state a human has to look at, not in
  this list" (`ci.yml` test-backend comment). Exclusions need a written reason.
- Details: TESTING.md.

## Extended Sections (Optional)

### Project-specific writing rules that affect code

- **Copy is product truth** (`AGENTS.md`). A missing value renders as an em dash or as a sentence
  saying it is missing, never as an invented number. Public numeric claims must be registered in
  `CLAIMS.md` (`scripts/verify_claims.mjs`).
- **No repository paths on the public surface** (`scripts/check-public-paths.mjs`,
  `frontend/src/lib/publicText.ts`).
- **No new palette hexes** outside the Apple/HDS set (`__tests__/staticShellContrast.test.js`,
  `data/design/hex-baseline.json`).
- **EN/BN parity**: every key in `frontend/src/lib/i18n.ts` has both languages
  (`__tests__/phaseBFrontend.test.js`).
