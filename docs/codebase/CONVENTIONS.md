### 2) Formatting and Linting

- **Formatter**: Prettier 3 — `.prettierrc`: `printWidth: 120`, `singleQuote: true`, `trailingComma: "all"`, `semi: true`, `tabWidth: 2`, `arrowParens: "always"`, `endOfLine: "lf"`.
- **Linter**: ESLint 9 **flat config** — `eslint.config.js`. Uses `@eslint/js` recommended + `typescript-eslint` recommended + `eslint-plugin-react-hooks`.
- **Most relevant enforced rules** (all currently at `warn`, a deliberate burn-down posture):
  - `@typescript-eslint/no-explicit-any: warn`
  - `@typescript-eslint/no-unused-vars: warn` with `argsIgnorePattern: ^_` / `varsIgnorePattern: ^_`
  - `no-console: warn` with `allow: ['warn','error','info']` for `**/*.{ts,tsx,js}` — turned **off** for `backend/**`, `api/**`, `scripts/**`, `*.config.*`, `e2e/**` (server/CLI context) and for `**/*.mjs`
  - `react-hooks` recommended rules scoped to `frontend/src/**`
- **Env-specific globals blocks**: browser + `process` for `frontend/src`; `serviceworker` for `frontend/src/serviceWorker.ts` and `frontend/public/**/*.js`; `node` for `.mjs`/backend/api/scripts; `jest + node` for tests.
- **Ignored paths** (do not lint generated/vendored output): `dist/**`, `frontend/dist/**`, `**/*.cjs`, `references/**`, `skills/**`, `.agents/**`, `rag_pipeline/**`, `docs/**`, `Models/**`, `load-tests/**`.
- **TypeScript strictness**: `frontend/tsconfig.json` sets `strict: true`, `target/module: ESNext`, `moduleResolution: bundler`, `jsx: react-jsx`, `skipLibCheck: true`, `forceConsistentCasingInFileNames: true`, `types: ["vite/client","node"]`. There is **no** `noUncheckedIndexedAccess` or `noImplicitOverride`. `backend/` and `api/` are plain JS — no type checking.
- **Run commands**: `npm run format` (Prettier write over `frontend/src/**/*.{ts,tsx}`, `backend/**/*.js`, `api/**/*.js`), `npm run lint:eslint` (`eslint .`), `npm run lint` (`tsc --noEmit`). CI runs lint and eslint but does **not** run Prettier in check mode, so formatting drift is not gated.

### 3) Import and Module Conventions

- **Module system**: ESM everywhere. Root `package.json` declares `"type": "module"`; a comment in `api/forecasts.js` records the consequence: *"CJS `require` fails here"*. Config files that must be CJS use the `.cjs` extension (`jest.config.cjs`, `babel.config.cjs`, `fix.cjs`).
- **Import grouping/order**: no linter-enforced ordering. The observed convention in backend/frontend sources is: Node builtins → third-party → local (`./`, `../`), e.g. `backend/utils/ai_fallback_engine.js` imports `node:crypto` first; `frontend/src/context/AuthContext.tsx` imports React, then `firebase/auth`, then `../services/firebase`. Node builtins use the `node:` prefix (`node:crypto`, `node:fs`).
- **Alias vs relative policy**: `@/*` → `frontend/src/*` for the frontend, declared in **both** `frontend/tsconfig.json#paths` and `frontend/vite.config.ts#resolve.alias` (the Vite config comment states Vite does not read tsconfig `paths`). `backend/` and `api/` use **relative imports only** — no path aliases.
- **Public exports**: named exports are the norm (`export function`, `export const`). `export default` is reserved for the serverless handler shape (`api/**/*.js` — required by Vercel) and for `clientError`/`db` convenience. Barrel files are not used; tests and modules import concrete paths.
- **`utils/` vs `backend/utils/`**: `utils/logger.js` lives at the repo root (not under `backend/`) so that both transports can reach it — `api/*.js` as `../utils/logger.js` and `backend/**` as `../../utils/logger.js`. It is genuinely shared but thinly adopted: only two modules import it today (`backend/utils/csvIngestion.js`, `api/ingest.js`); everything else uses `console.*` with a `[tag]` prefix.

### 4) Error and Logging Conventions

- **Error strategy by layer** (documented policy, SEC-13, in `backend/utils/clientError.js`):
  - **4xx** — the status was set by the project's own validation code, so the message is caller-facing and returned as-is.
  - **5xx** — **always a generic message** (`{ error: fallback }`); the real error is logged server-side with its stack. Raw driver/database text must never cross the wire.
  - **Validation** — `zod` schemas at the edge (`api/ingest.js`, `backend/middleware/validation.js`); row-level CSV validation messages are whitelisted as safe because they are written for the operator (`api/ingest.js` uses `/^Row \d+: /` to distinguish them).
  - **Fail-closed auth** — `verifyApiKey` returns **503** (not 401) when `BACKEND_API_KEY` is unset, so an unconfigured deployment denies rather than allows.
- **Logging style**:
  - Shared wrapper: `utils/logger.js` — `logger.info` / `logger.error`, prefixed `[INFO]` / `[ERROR]`. Its own comment says it "can be swapped for winston or pino" (i.e. intentionally minimal).
  - Subsystem tags: `console.log('[inference] …')`, `console.warn('[config] …')`, `console.error('[tfjs] …')` — a bracketed lowercase tag naming the module/script. Observed tags include `[inference]`, `[tfjs]`, `[config]`, `[push]`, `[content]`, `[alerts-snapshot]`, `[rag-freshness]`, `[npm-audit-ci]`, `[hds]`.
  - Structured request log: `backend/middleware/requestId.js` emits a single-line JSON record (`ts`, `level`, `msg: 'http_request'`, `requestId`, `method`, `path`, `status`, `durationMs`) on every response and echoes `X-Request-Id`. **Required context field: `requestId`** — it is the correlation key from a client report to server and proxy logs.
  - Startup configuration assertions: `backend/server.js` collects `problems` (→ `console.error`) and `warnings` (→ `console.warn`) at boot, all tagged `[config]`, and is deliberately non-fatal so local dev still boots.
- **Sensitive-data redaction**: SMS previews redact credentials when `SMS_DRY_RUN=true` (`.env.example` comment). Release notes in `.env.example` state that provider keys previously committed there "are now placeholders; the real values must be rotated (they exist in git history)".

### 5) Testing Conventions

- **Test file naming/location rule**: three separate conventions, one per runner.
  - Jest: `__tests__/<subject>.test.js` at the repo root for backend/API subjects, and co-located `__tests__/` folders inside `frontend/src/**` for client subjects (e.g. `frontend/src/lib/__tests__/`, `frontend/src/components/__tests__/`).
  - Playwright: `e2e/<area>.spec.ts` (`smoke`, `critical-paths`, `mobile-responsive`).
  - pytest: `scripts/tests/test_<subject>.py`, including workflow-file guards (`test_workflows.py`) and policy guards (`test_model_claims.py`, `test_secret_scan.py`).
- **Mocking strategy norm**: `jest.mock` for module boundaries, `supertest` + `node-mocks-http` for HTTP handlers, and explicit reset hooks exposed by production code for singletons — `resetForecastStore()` in `backend/forecastStore.js` and `resetAlertStore()` in `backend/alerts/store.js` are documented as "test/maintenance hook". `jest.config.cjs` sets `transformIgnorePatterns: []` (transform everything) rather than a per-package allowlist.
- **Coverage expectation**: enforced in `jest.config.cjs` — global thresholds `statements: 32`, `branches: 35`, `functions: 30`, `lines: 31`, scoped by `collectCoverageFrom` to `backend/**/*.js`, `api/**/*.js`, `frontend/src/utils/**/*.ts`. The config comment states this is the measured 2026-08-28 baseline (~32% statements) minus a margin, to be ratcheted upward. The CI frontend job passes `--coverageThreshold='{}'` to disable the backend-calibrated gate for frontend-only runs (baseline ≈17% statements).
- **Test-selection gotcha encoded in CI**: `--testPathIgnorePatterns` is array-valued, so a bare selector after it is swallowed; CI passes the full ignore list explicitly and `scripts/tests/test_workflows.py::test_backend_jest_step_has_no_bare_selector` guards it.
