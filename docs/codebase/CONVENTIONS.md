### 2) Formatting and Linting

- **Formatter:** Prettier 3 — `printWidth: 120`, `singleQuote: true`, `trailingComma: "all"`,
  `semi: true`, `tabWidth: 2`, `arrowParens: "always"`, `endOfLine: "lf"` (`.prettierrc`).
  Scope enforced by the npm script: `frontend/src/**/*.{ts,tsx}`, `backend/**/*.js`, `api/**/*.js`
  (`package.json` → `format`).
- **Linter:** ESLint 9 flat config with `typescript-eslint` 8 — `eslint.config.js`.
  Ignores `dist/**`, `**/*.cjs`, `docs/**`, `skills/**`, `Models/**`, `references/**`, `.agents/**`.
- **Most relevant enforced rules:**
  - `@typescript-eslint/no-explicit-any: warn` (the largest single warning class)
  - `@typescript-eslint/no-unused-vars: ['warn', { argsIgnorePattern: '^_', varsIgnorePattern: '^_' }]`
    — hence the `_unused` and `_req` parameter convention
  - `no-console: ['warn', { allow: ['warn','error','info'] }]` — `console.log` is banned except in
    explicitly exempted files (`scripts/**`, `serverless/**`, `utils/**`, `e2e/**`, `*.mjs`)
  - `no-empty: ['error', { allowEmptyCatch: true }]`
  - `react-hooks` recommended rules for `frontend/src/**/*.{ts,tsx}`
- **Commands:** `npm run lint` (tsc `--noEmit`, **0 errors**), `npm run lint:eslint`
  (`eslint . --max-warnings 685`), `npm run format`.
- **Measured 2026-10-02:** tsc passes; ESLint reports **0 errors / 683 warnings** — i.e. only 2
  warnings of headroom before the `--max-warnings 685` budget fails CI.

### 3) Import and Module Conventions

- **Module system:** ESM everywhere (`"type": "module"` at the root and in every workspace).
  Server-side relative imports **always** carry the `.js` extension
  (`import { db } from './db.js'`). Config files that must be CommonJS use `.cjs`
  (`jest.config.cjs`, `babel.config.cjs`, `apps/mobile/metro.config.cjs`).
- **Import grouping (observed, not enforced by a plugin):** node built-ins → third-party →
  workspace/alias imports → relative imports, with the relative group last
  (`backend/routes/forecasts.js`, `serverless/v1/forecasts/bulk.js`, `frontend/src/App.tsx`).
- **Aliases vs relative:** the frontend uses the `@/` alias for `frontend/src/*` and bare
  `@hazardnet/*` specifiers for workspace packages; the server and scripts use relative paths
  exclusively. `frontend/tsconfig.json` `paths`, `frontend/vite.config.ts` `resolve.alias` and
  `jest.config.cjs` `moduleNameMapper` must be kept in sync — the vite config comment records that
  Vite does not read tsconfig `paths`.
- **Barrels:** each `packages/*/src/index.ts` re-exports its public surface and the packages
  expose sub-path entries (`@hazardnet/core/forecasts`, `@hazardnet/api/client`,
  `@hazardnet/design-system/tokens`, …). `frontend/src/design-system/index.ts` and
  `frontend/src/components/brand/index.ts` are the only frontend barrels; there is no
  top-level `src/index.ts`.
- **Packages are consumed as TypeScript source** (`"main": "./src/index.ts"`), so there is no
  build step between editing a package and running the app or the tests.
- **Serverless loaders must be literal:** `routes: { bulk: () => import('…/bulk.js') }` — a
  computed specifier would break the platform bundler's tracing (documented in every `api/**` file).

### 4) Error and Logging Conventions

- **Client-facing errors (server):** `clientError(res, err, { scope, fallback })` from
  `backend/utils/clientError.js`. 4xx messages authored by our own validation are returned as-is;
  **5xx always returns a generic string** (`'Internal server error'`) and logs the stack
  server-side with the scope tag (`[api/v1/forecasts/bulk] …`). Introduced after a live audit found
  raw driver/hostname text reaching clients (SEC-13).
- **Validation:** `zod` schemas at the boundaries (`packages/api/src/endpoints.ts`,
  `packages/core/src/contracts.ts`); CSV/row validation returns structured
  `{ ok: false, error }` results rather than throwing (`backend/utils/forecastRow.js`,
  `backend/utils/csvIngestion.js`). The CSV parser additionally defends against spreadsheet formula
  injection (`backend/utils/csvSafety.js`).
- **Fail-closed auth:** `verifyApiKey()` returns **503** when `BACKEND_API_KEY` is unset rather
  than allowing the write; comparisons are constant-time (`backend/utils/apiKeyAuth.js`).
- **Logging style:** one structured JSON line per HTTP request from
  `backend/middleware/requestId.js` (`{ts, level, msg:'http_request', requestId, method, path,
  status, durationMs}`), echoed to the client as `X-Request-Id`. Serverless handlers use
  `utils/logger.js` (`info/warn/error/debug`, `DEBUG` env gate). Server startup emits
  `[config] …` warnings/errors and `[server] …` lifecycle lines.
- **Sensitive-data redaction:** `console.log` is stripped in release mobile builds
  (`apps/mobile/App.tsx`); `assertNoSecretsInBundle()` runs in dev
  (`apps/mobile/src/lib/security/sanitize.ts`); scripts use
  `scripts/lib/public-text.mjs` so no repository path reaches a shipped document (also enforced by
  `scripts/check-public-paths.mjs`); `scripts/check-secrets.sh` and `scripts/security_audit.sh`
  scan the working tree for leaked secrets.

### 5) Testing Conventions

- **Placement/naming:** root Jest suites in `__tests__/*.test.js` (with `alerts/`, `api/`,
  `mobile/` sub-folders); component/unit tests co-located in `frontend/src/**/__tests__/*.test.ts(x)`;
  package tests in `packages/*/__tests__/*.test.ts`; mobile component tests in
  `apps/mobile/__tests__/*.test.tsx`; E2E in `e2e/*.spec.ts`; pipeline/workflow tests in
  `scripts/tests/test_*.py`.
- **Frameworks:** Jest 29 + `babel-jest` (transform everything, `transformIgnorePatterns: []`),
  jsdom environment by default with `@jest-environment node` file pragmas for node-only suites
  (`__tests__/securityHeadersParity.test.js`), `jest-axe` for a11y assertions, `supertest` +
  `node-mocks-http` for HTTP surfaces, `@testing-library/react` / `react-native` for components,
  `jest-expo`+`react-native` preset for mobile, pytest for Python.
- **Mocking norm:** React Native/Expo native modules are mapped to hand-written stubs in
  `__tests__/__mocks__/` (14 files) via `jest.config.cjs` `moduleNameMapper`; services are mocked
  with `jest.mock()` in setup for mobile (`apps/mobile/jest.setup.cjs`); network calls are mocked
  with `jest.fn()`/`global.fetch` stubs rather than a server.
- **Coverage expectation:** global threshold `statements 32 / branches 35 / functions 30 / lines 31`
  (`jest.config.cjs`), scoped to `backend/**`, `api/**`, `frontend/src/utils/**`,
  `packages/{core,api,analytics}/src/**`. Measured 2026-10-02 in the backend job scope:
  **62.6 % statements / 59.5 % branches / 61.1 % functions** (85 files) — the gate is currently
  ~30 points below actual coverage.
- **A distinctive convention:** many suites are *contract/artifact gates* rather than unit tests —
  they assert properties of committed files (claims registry, CSP parity between the two
  `vercel.json`s, NASA token compilation, no repository paths in shipped text, model artifacts not
  served, design-token parity, public-text rules).

## Extended Sections (Optional)

### The house style: "explain the why in a header comment"

Nearly every non-trivial module opens with a multi-paragraph comment that states the problem, the
constraint and the decision — often naming the incident that produced it. Examples:
`serverless/dispatch.js` (Hobby function budget), `frontend/vite.config.ts` (the Rolldown/Leaflet
white-screen fix and the Vercel-analytics loader gate), `backend/security/csp.js` (three drifting
CSP editions), `backend/utils/chatService.js` (chat 404 in production),
`backend/middleware/serverlessGuard.js` (unmetered endpoints), `scripts/build_freshness_artifact.mjs`
("never invent"). New code is expected to follow this: a change without a stated reason reads as
arbitrary in review.

### Layer-specific error handling

| Layer | Strategy | Evidence |
|-------|----------|----------|
| Vercel handler | `guardRequest()` → method check → parse → try/catch → `clientError()`; dispatch failures answered as JSON 500 | `serverless/dispatch.js`, `serverless/v1/forecasts/bulk.js` |
| Express route | try/catch → `next(err)` or `clientError`; rate-limit rejections return `{ error: message }` | `backend/routes/forecasts.js`, `backend/middleware/rateLimit.js` |
| Domain (`alerts/**`) | Throws typed errors; the store refuses illegal transitions, it does not negotiate | `backend/alerts/lifecycle.js`, `backend/alerts/store.js` |
| Client | Result objects/validation, never exceptions across the network boundary; 3-level fallback chain | `frontend/src/lib/forecasts.ts`, `frontend/src/lib/alerts.ts` |
| Build scripts | `process.exit(1)` with `::error::` annotations where CI reads them | `scripts/check-vercel-functions.mjs`, `scripts/check-public-paths.mjs` |
