### 2) Formatting and Linting

- **Formatter:** Prettier 3.9.9 — `.prettierrc`: `printWidth 120`, `singleQuote true`,
  `trailingComma "all"`, `semi true`, `tabWidth 2`, `arrowParens "always"`, `endOfLine "lf"`.
  Run via `npm run format`, which is scoped to `frontend/src/**/*.{ts,tsx}`, `backend/**/*.js`
  and `api/**/*.js` — **not** `serverless/`, `scripts/` or `packages/`.
- **Linter:** ESLint 9.39.5 flat config (`eslint.config.js`) + `typescript-eslint` 8 +
  `eslint-plugin-react-hooks` 5. The config's own header states the policy: *"Formatting is
  Prettier's job — no stylistic rules here. Existing violations are not the bar for new code:
  tighten to `--max-warnings 0` in CI once the legacy count is burned down."*
- **`npm run lint` is `tsc`, not ESLint.** `tsc -p frontend/tsconfig.json --noEmit`. The ESLint
  gate is a separate script (`lint:eslint`) and a separate CI step.
- **Most relevant enforced rules:**
  - `@typescript-eslint/no-explicit-any` → **warn**
  - `@typescript-eslint/no-unused-vars` → **warn**, with `argsIgnorePattern: '^_'` and
    `varsIgnorePattern: '^_'` (prefix an intentionally-unused binding with `_`)
  - `no-console` → **warn**, allowing `warn`, `error`, `info` (so `console.log` is the only
    banned level) — and **off** entirely for `backend/`, `api/`, `serverless/`, `utils/`,
    `scripts/`, `e2e/` and `**/*.config.js`
  - `no-empty` → **error**, `allowEmptyCatch: true` (empty `catch {}` is the sanctioned idiom)
  - `react-hooks/recommended` → applied to `frontend/src/**` only
- **Measured lint state (this sandbox, HEAD):** `✖ 579 problems (0 errors, 579 warnings)` against
  a budget of `--max-warnings 685` — **106 warnings of headroom**. Breakdown:

  | Count | Rule |
  |---|---|
  | 353 | `@typescript-eslint/no-unused-vars` |
  | 180 | `@typescript-eslint/no-explicit-any` |
  | 24 | `react-hooks/exhaustive-deps` |
  | 15 | *unused `eslint-disable` directive* (no `ruleId`; all in `apps/mobile/**`, `frontend/src/lib/gibs.ts`, two `__tests__/api/*` files) — **`--fix`-able** |
  | 7 | `no-console` |

  ESLint reports *"0 errors and 15 warnings potentially fixable with the `--fix` option."*
- **Run commands:** `npm run lint` (tsc) · `npm run lint:eslint` · `npm run format`
- **Ignore list** (`eslint.config.js`): `dist/**`, `frontend/dist/**`, `node_modules/**`,
  `**/*.cjs`, `references/**`, `skills/**`, `.agents/**`, `docs/**`, `Models/**`,
  `audit_temp/**`, `load-tests/**`. Note `skills/**`, `references/**`, `.agents/**`,
  `audit_temp/**` and `load-tests/**` **do not exist at HEAD** (see CONCERNS §2).
- **TypeScript strictness:** `frontend/tsconfig.json` sets `strict: true` (the whole family),
  `target/module: ESNext`, `moduleResolution: "bundler"`, `jsx: "react-jsx"`,
  `useDefineForClassFields`, `forceConsistentCasingInFileNames`, `resolveJsonModule`,
  `skipLibCheck`. `include` is `src/**/*.ts(x)` only — **`apps/`, `packages/` and `backend/` are
  not type-checked by this gate**; `packages/*` carry their own `tsconfig.json`, and
  `backend/`+`serverless/`+`api/` are plain JavaScript.

### 3) Import and Module Conventions

- **Grouping/order** (no plugin enforces it; the convention is consistent by review). Observed in
  `frontend/src/pages/AdvisoriesPage.tsx` and `frontend/src/App.tsx`:
  1. `react` and React-adjacent (`react`, `react-dom`)
  2. third-party libraries (`react-router-dom`, `framer-motion`, `@tanstack/react-query`, `lucide-react`, `react-hot-toast`)
  3. a **blank line**
  4. workspace packages (`@hazardnet/core`, `@hazardnet/design-system`, `@vercel/analytics/react`)
  5. local modules — context/providers, then components, then `lib/`, then `hooks/`
  Named imports are expanded one-per-line when long (see the 28-icon `lucide-react` block).
- **Alias vs relative policy:** aliases for **cross-package** imports only —
  `@hazardnet/{core,api,design-system,analytics}` and `@/*`. Everything inside a workspace is
  **relative** (`../components/MaterialIcon`, `./lib/motion-interpolate`). The alias table is
  declared in **three places that must be kept in sync by hand**: `frontend/tsconfig.json` `paths`,
  root `jest.config.cjs` `moduleNameMapper`, and `apps/mobile/jest.config.cjs` `moduleNameMapper`.
- **Public exports / barrel policy:** every workspace package has a barrel
  (`packages/*/src/index.ts`). Wildcard re-export is the default
  (`export * from './contracts'`), with one deliberate exception worth copying:
  `packages/core/src/index.ts` re-exports `sectorAdvisories` **value-by-value** because
  `alertPolicy` already exports an `EmergencyContact` of a different shape —
  *"Naming the exports keeps the collision visible instead of resolving it silently."*
  It also renames on export: `EmergencyContact as AdvisoryEmergencyContact`.
  `frontend/src/` has **no** barrels; components import each other by path.
- **Extension policy:** ESM sources import each other **with the `.js` extension**
  (`import { corsMiddleware } from './middleware/cors.js'`, `backend/server.js:5`) — required by
  Node ESM. TypeScript sources omit extensions.
- **Lazy-import discipline in `api/`:** specifiers must stay **literal** so Vercel's bundler can
  trace them (`api/[endpoint].js` header, `serverless/dispatch.js`).
- **Config single-source rules, stated in-file:**
  - *"Do not introduce additional Firebase config literals elsewhere — the removed
    `src/firebase.ts` (an unused second project) is the cautionary tale."* (`frontend/src/lib/config.ts`)
  - The CSP lives in `backend/security/csp.js` so the self-host deployment cannot drift from the
    two Vercel configs (`backend/server.js:76-79`).

### 4) Error and Logging Conventions

- **Error strategy by layer:**

  | Layer | Strategy | Evidence |
  |---|---|---|
  | Domain / lib | `throw new Error(...)` with a message written for a developer — 51 `throw new` sites across `backend/` | `git grep -c 'throw new' backend` |
  | HTTP boundary | **`clientError(res, err, { scope, fallback })`** — 4xx messages are returned as-is (our own validation wrote them); **5xx always returns a generic string** and logs the stack server-side via `logServerError(scope, err)` | `backend/utils/clientError.js` (21 call sites) |
  | Serverless dispatch | An unmatched path returns a **JSON 404 metered as a `read`**, never the edge's HTML 404 | `serverless/dispatch.js` header |
  | Config | **Fail closed.** Missing `BACKEND_API_KEY` → 503 on privileged endpoints; missing `FRONTEND_ORIGIN` in production → cross-origin requests rejected, not reflected | `backend/utils/apiKeyAuth.js`, `backend/middleware/cors.js` |
  | Startup | Non-fatal assertion IIFE separating `problems[]` from `warnings[]`, logged before the app listens | `backend/server.js:36-63` |
  | Upstream AI | Circuit breaker (45 s cooldown) + cascade + deterministic heuristic last resort; a 429 *"trips the breaker & initiates the next fallback tier"* | `backend/utils/ai_fallback_engine.js:39-109,466-512` |
  | Store | Firestore failure flips `firestoreAvailable = false` and falls back to the committed snapshot, re-probing later | `backend/forecastStore.js:172-183` |
  | UI | Root `ErrorBoundary` + a **four-state surface per page** (loading / empty / error+retry / success); absent data is *reported as absent in words*, never as zero or a dash | `frontend/src/App.tsx`, `data/design/four-state-baseline.json`, `PRODUCT.md` principle 2 |
  | Empty catch | Sanctioned: `no-empty` is configured `allowEmptyCatch: true` | `eslint.config.js` |

- **Logging style.** Two idioms coexist and are each correct for their runtime:
  - **Serverless / shared:** `utils/logger.js` — `logger.{info,warn,error,debug}`, prefixing
    `[info]`/`[warn]`/`[error]`, JSON-stringifying non-strings, `debug` gated on `process.env.DEBUG`.
    Its header states it *"can be swapped for a structured logger (pino/winston) without changing
    call sites."*
  - **Everywhere else:** bare `console.*` with a **bracketed scope tag** —
    `[config]`, `[AI Fallback Engine]`, `[check-bundle]`, `[fetch]`, `[ingest]`, `[deploy]`,
    `[git]`, `[test]`, `[vercel-functions]`. Measured across `backend/`, `serverless/`, `api/`,
    `scripts/`, `frontend/src/`: 229 `console.log`, 123 `console.error`, 45 `console.warn`,
    15 `console.info`. `console.log` survives because `no-console` is off for those globs;
    only **7** `no-console` warnings remain repo-wide.
  - **Required context fields:** a `scope` string on every server-error log
    (`clientError(res, err, { scope: 'api/v1/forecasts/bulk' })`), and a per-request
    `requestId` attached by `backend/middleware/requestId.js` for correlated logging (BE-04).
  - **Pipeline scripts** write GitHub-native annotations (`::warning::`, `::error::`) and a
    `$GITHUB_STEP_SUMMARY` block rather than logging for humans
    (`daily_advisory_ingest.yml`).
- **Sensitive-data redaction rules:**
  - **5xx detail never reaches a client** — the whole reason `clientError.js` exists (a
    2026-09-17 live audit found raw `err.message` carrying internal hostnames, driver text, file
    paths and query fragments).
  - `x-powered-by` is disabled to minimise fingerprinting (SEC-05, `backend/server.js:70`).
  - The analytics tracker strips **PII-shaped keys** before a batch leaves the browser, honours
    Do Not Track, and is off unless `VITE_ANALYTICS_ENABLED=true`
    (`packages/analytics/src/streaming.ts`).
  - `KAGGLE_USERNAME`/`KAGGLE_KEY` are annotated server-side-only in `.env.example`;
    `scripts/check-secrets.sh` and `scripts/verify-actions-secrets.sh` run as gates.
  - Secret values are never committed: `.env.example` ships **all 38 variables empty**.

### 5) Testing Conventions

- **Test file naming/location:** `*.test.{js,ts,tsx}` for Jest, `*.spec.ts` for Playwright.
  Placement is **both** co-located (`frontend/src/lib/__tests__/`, `frontend/src/pages/__tests__/`,
  `packages/core/__tests__/`, `apps/mobile/__tests__/`) **and** centralised (`__tests__/` at the
  root, subdivided into `alerts/`, `api/`, `mobile/`). Both are collected by the one root Jest
  project; `e2e/`, `__mocks__/`, `apps/mobile/` and `manuscript/` are excluded from it by
  `testPathIgnorePatterns`.
- **Mocking strategy norm:** hand-written **module mocks** in `__tests__/__mocks__/` mapped by
  `moduleNameMapper` — 14 mocks covering `react-native`, every Expo module, React Navigation,
  `async-storage`, `netinfo`, `reanimated`, `gesture-handler`, `safe-area-context`, `screens`,
  `svg`/FlashList, TanStack Query, plus `empty-string.js` for `.md` assets. The root config's
  `transformIgnorePatterns: []` transforms **everything** deliberately: *"Small dependency set,
  many ESM-only packages … transform everything instead of maintaining a per-package exception
  list that breaks on every new ESM dependency."*
- **Coverage expectation:** enforced by `jest.config.cjs` `coverageThreshold.global` —
  **statements 32 / branches 35 / functions 30 / lines 31**, described in-file as a floor set at
  the measured 2026-08-28 baseline minus a margin, to *"ratchet upward as tests land."*
  Measured 2026-10-10: **65.34 / 60.59 / 64.48 / 66.30** — roughly double the floor.
  Scope is `collectCoverageFrom`: `backend/**/*.js`, `api/**/*.js`, `frontend/src/utils/**/*.ts`,
  `packages/{core,api,analytics}/src/**/*.ts` — **components, pages, hooks and `serverless/` are
  not in the coverage denominator.**
- **Design gates are tests.** The convention that makes this repo unusual: a design or copy rule
  is expressed as a Jest suite plus a frozen JSON ledger in `data/design/`, whose counts *may only
  go down*. `__tests__/iconFamily.test.js` is the model — `BASELINE_IMPORTERS = 61`, asserted with
  `toBeLessThanOrEqual`, measured today at **54**.
- Full detail in [`TESTING.md`](./TESTING.md).

### Language-specific strictness

| Surface | Language | Strictness | Gate |
|---|---|---|---|
| `frontend/src/**` | TypeScript | `strict: true`, `moduleResolution: bundler` | `npm run lint` (tsc) + ESLint + `react-hooks` |
| `packages/*/src/**` | TypeScript | own `tsconfig.json` per package; **not** covered by the root tsc gate | compiled through the consumers' aliases; unit-tested |
| `apps/mobile/src/**` | TypeScript | resolved by `apps/mobile/jest.config.cjs`; **not** covered by the root tsc gate | `test-mobile` CI job |
| `backend/`, `api/`, `serverless/`, `scripts/`, `utils/` | JavaScript (ESM) | no type-check at all | 106 Jest suites + `ci.yml` step *"Serverless functions load as ESM"* |
| `apps/windows/windows/**` | C++/IDL | MSBuild; `CppProperties.json` is IntelliSense only | built on `v*` tags only (owner Action 14 asks for a PR job) |
| `scripts/tests/*.py`, `scripts/validate_forecasts.py` | Python 3.11 | — | `pytest` (122 tests) |

The asymmetry is the practical convention to know: **the JavaScript half of the runtime has no
type gate**, so its correctness rests on the 106-suite backend/API Jest subset and on the ESM-load
step in `ci.yml`.

### Repo-specific commit / branching conventions

- Branches observed in history: `arena/<sandbox-id>-hazardnet` (agent sessions, merged by PR) and
  `main`. Merges are PR merges with the number appended to the subject (`(#93)`).
- Bot commits are namespaced by scope so they can be filtered: `chore(ops):` for the site-health
  probe, `chore(advisory):` for the daily ingest (which adds `[skip ci]` so an artifact commit
  does not re-trigger CI).
- `ci.yml` uses `concurrency: { group: ci-${{ github.workflow }}-${{ github.ref }},
  cancel-in-progress: true }`; the ingest and wind workflows use `cancel-in-progress: false`
  because they commit.
