### 6) Owner decisions (asked and answered, 2026-10-02)

Nine questions were put to the owner while this map was written. Their answers, and what was
done with each:

1. **`.vs/` — "Remove it."** Done: `git rm -r --cached` plus deletion from disk (69 MB);
   `.gitignore` already guards it. The duplicated hero videos (224.2 MB) and the Windows
   artefacts were **not** touched — the answer was scoped to `.vs/`, and no history rewrite
   (`git filter-repo`) was authorised, so the objects remain in the existing commits.
2. **Mobile/Windows — "I don't know, need thorough review and audit."** Audited:
   `docs/audits/2026-10-02-mobile-windows-support-audit.md`. Both targets are live and
   released; the mobile suite could not run from its documented command (a cwd-relative Babel
   path), nothing ran it in CI, and one script entry pointed at a file that was never written.
   All three are fixed; 9 suites / 62 tests now pass in ~15 s from the repository root, and a
   `test-mobile` CI job runs them. Open handles after the run remain (the job uses
   `--forceExit`).
3. **Android and Windows — "released packages of this repo."** Recorded as a standing
   constraint: neither tree may be deleted or de-scoped. Android's native project is generated
   by `expo prebuild` (gitignored, rebuilt by `app-releases.yml`); Windows' is committed
   (37 files) and builds to an MSIX.
4. **Kaggle advisory dataset — "there are many fields which aren't present at the current
   system, we've to introduce them in the frontend."** Analysed and fixed. The published CSV
   (`hazardnet_advisories_latest.csv`, 22 columns, 128 rows = 64 districts x 2 horizons) is
   byte-identical in shape to `ADVISORY_CSV_COLUMNS`, and the backend mapper and validators
   already carried all 22. The loss was in `frontend/src/lib/forecasts.ts`: `parseForecastRow`
   was an allowlist that dropped `advisory_tier`, `final_severity`, `model_severity_raw`,
   `physics_override`, `prob_top1..3`, `latitude`, `longitude`, `data_source` and
   `model_version`, so three components that already read `advisory_tier` fell back to a tier
   derived client-side from `severity_score` while the published one sat unused in the payload.
   The parser now carries them (with range and bounding-box validation), the shared Zod
   contract models them, `DistrictForecastRecords` shows tier / final severity / top-3, and a
   new `AdvisorySignalCard` renders the four severity tracks and the provenance line.
5. **`docs/ops/owner-actions.md` — "No idea about this file."** Created and reconstructed from
   the 12 in-tree citations (the IDs the code already referenced: Action 5, 8, 9, §2a-bis),
   marked **unassigned**, with Actions 10–15 added for what this pass found. Entries that
   could not be recovered from a citation are marked *not reconstructed* rather than invented.
6. **`packages/analytics` and `plugins/` — "Keep and make it functional for live streaming
   deployment."** Both kept. The analytics package was an interface plus a no-op that nothing
   imported; it now ships `createStreamingTracker` (batching, queue cap, one retry then drop,
   `sendBeacon` on unload, PII-shaped key stripping, opt-in + Do Not Track) with 12 tests, a
   `POST /api/v1/telemetry` endpoint that rides the existing `api/v1/[resource].js` entry point
   (so the 12-function budget is untouched) and validates before acknowledging, and thin web
   wiring that stays off unless `VITE_ANALYTICS_ENABLED=true`. The plugin manifest no longer
   claims `enabled: true` for modules that do not exist, and a test fails if an enabled entry
   stops resolving.
7. **`VERCEL_FUNCTIONS.md` — "Fold it up to architecture."** Folded into `ARCHITECTURE.md` as
   "Vercel serverless surface (the 12-function budget)"; the file is deleted and all 17
   references (source, tests, `eslint.config.js`, `ci.yml`) point at the new section. The
   `docs/codebase/` directory is back to the seven files the skill's contract specifies.
8. **Secret rotation — "Check out on that."** There was no cadence and no record of any
   rotation, and the secrets-audit workflow is dispatch-only. Added `docs/ops/secret-rotation.md`
   (cadence per credential, with the reasoning), `data/security/secret-rotation.json` (the
   register, with `last_rotated: null` rather than invented dates), `scripts/check-secret-rotation.mjs`
   (`npm run check:rotation`; unknown dates warn, overdue dates fail), a monthly scheduled
   workflow, and 11 tests. Action 1 in `docs/ops/owner-actions.md` is the human half.
9. **`profiles` public read — "Unintentional."** Narrowed. `allow get, list: if true` meant an
   anonymous client could read and enumerate every account's email, phone, WhatsApp, address
   and pinpoint coordinates. Reads are now opt-in per row (`profile_visibility == 'public'`)
   and `list` is capped at `limit(1)` — rules cannot see which field a query filters on, so the
   limit is the anti-scraping control. The client queries now send `limit(1)`, and a
   permission-denied username lookup is treated as *taken* rather than *available* (it was the
   opposite, which would have let a second user claim a name someone already held). The same
   pass found that `boundedString` rejected `null`, so avatar deletion was already breaking on
   the rules; `nullableString` fixes it. Follow-up (Action 10): Firestore cannot hide
   individual fields in a read, so a public profile still carries contact data — the durable
   fix is a `publicProfiles` mirror.
