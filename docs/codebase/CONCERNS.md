### 6) `[ASK USER]` Questions

1. **`[ASK USER]` Which Firestore database is authoritative — `(default)` or `ai-studio-hazardnet-…`?** `.env.example` says `default`; the code, the tracked config and the writer say `ai-studio-hazardnet-55b49dbf-…`. Which one does production actually read and write?
2. **`[ASK USER]` Is the Postgres / `FORECAST_STORE` cutover still planned, deliberately reverted, or abandoned?** ADR 0002 describes the expand phase as merged, but the selector, the Postgres store, `scripts/db/002_forecasts_postgres.sql`, `scripts/migrate-firestore-to-postgres.mjs`, the fail-loud startup check and the 16-test suite are all absent; no application code imports `firebase/*`; and `backend/forecastStore.js` is Firestore-only. Should ADR 0002 be corrected to record the reversion, or should the implementation be restored?
3. ~~**`[ASK USER]` What should `FORECAST_STORE` be set to, and is `firebase` a real mode?**~~ ✅ **RESOLVED 2026-09-20** — `FORECAST_STORE=firestore` is the single, validator-accepted value (`Allowed: firestore, local, memory, json`), and `.env.example` now ships it.
4. **`[ASK USER]` Is the API/store write path supposed to be live at all?** Today the website is served the committed snapshot and the store push is opt-in and off (`PUSH_TO_API` default `false`), while the store write is denied by rule.
