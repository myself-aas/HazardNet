### 2) Entry Points

- **Web app (browser):** `frontend/src/main.tsx` → `frontend/src/App.tsx` (all routes, lazy
  page chunks, `QueryClientProvider`, `AuthProvider`). Prerendered HTML is produced at build
  time by `frontend/scripts/prerender.mjs`; the service worker is `frontend/public/serviceWorker.js`.
- **Self-hosted API/server:** `backend/server.js` — bound to a port **only** when invoked
  directly (`npm start`, `npm run dev`, `npm run dev:api`); exporting the Express `app` for
  `supertest`. Defaults to `:3000`; dev expects `:3001` because the Vite dev server owns `:3000`.
- **Serverless API (production):** `api/[endpoint].js`, `api/chat/[action].js`,
  `api/v1/[resource].js`, `api/v1/alerts/[action].js`, `api/v1/forecasts/[action].js`,
  `api/v1/weather/batch.js` → `createDispatcher()` in `serverless/dispatch.js` → per-endpoint
  handlers in `serverless/**`.
- **Mobile app:** `apps/mobile/App.tsx` (Expo entry `expo/AppEntry.js` via `apps/mobile/package.json`
  `main`); navigation root `apps/mobile/src/navigation/RootNavigator.tsx`.
- **Windows app:** `apps/windows/App.windows.tsx` + `apps/windows/windows/HazardNet/` (C++ WinUI host).
- **Tooling/CLI:** `scripts/*.mjs` (snapshot/freshness/content builders, gates),
  `scripts/*.py` (validation), `scripts/*.sh` (secret scan, security audit, monitoring setup,
  Actions-secrets verification), `frontend/scripts/prerender.mjs`, `frontend/scripts/export-blog-index.mjs`.
- **CI:** `.github/workflows/ci.yml` (6 jobs: `test-backend`, `test-frontend`,
  `test-pipeline-scripts`, `test-e2e`, `verify`, `security-audit`),
  plus scheduled `daily_advisory_ingest.yml` (05:30 UTC) and `site-health.yml` (every 30 min).
- **How entry is selected:** npm scripts in `package.json` (`dev`, `dev:api`, `start`, `build`)
  and `frontend/package.json` (`dev`, `build`); Vercel uses `vercel.json`
  (`buildCommand: npm run build`, `outputDirectory: dist`) and the `api/` directory convention.

### 3) Module Boundaries

| Boundary | What belongs here | What must not be here |
|----------|-------------------|------------------------|
| `frontend/src/**` | Presentation: pages, components, hooks, client-side lib, SEO/structured data, Firebase client wiring | Server secrets; direct `process.env` secrets (only `VITE_*`); model artifacts |
| `frontend/public/data/**` | Committed, published artifacts (forecast snapshot, alerts snapshot, freshness, historical catalog, content index) — regenerated by `scripts/` | Hand-edited data (CI compares the committed content index against the build) |
| `backend/routes/**` | HTTP surface: parse → validate → call a service/util → respond | Business rules (live in `backend/alerts/*`, `backend/utils/*`) |
| `backend/alerts/**` | The alert domain: policy-as-data, assessment, lifecycle state machine, evidence, notifications, channels, store | Express concerns (no `req`/`res` types here) |
| `backend/utils/**` | Shared domain + integration helpers (forecast row/serve, CSV safety, AI cascade, Open-Meteo, Gemini grounding) duplicated-free for both runtimes | Runtime-specific request handling (Vercel handlers live in `serverless/`) |
| `serverless/**` | Thin Vercel handlers: guard → parse → call `backend/**` → JSON. Must call `guardRequest()` | Business logic (imported from `backend/**` so both runtimes are identical by construction) |
| `api/**` | Dispatch tables only (one file per URL family) | Handler implementations |
| `packages/core` | Pure TypeScript, no React/DOM/RN (contracts, forecast math, freshness, geo, dedupe, query keys) | Platform APIs |
| `packages/api` | Cross-platform fetch client + Zod-validated endpoint wrappers + retry policy | UI code |
| `packages/design-system` | Tokens (NASA HDS / Material 3 Expressive / Meridian) — React optional for the token entry | App-specific components |
| `packages/analytics` | Canonical analytics event names + `Tracker` interface | SDK bindings (each app supplies its own) |
| `apps/mobile/src/**`, `apps/windows/src/**` | Native clients; they consume `@hazardnet/*` and the public API | Duplicated domain logic (should come from `packages/core`) |
| `scripts/**` | Build/publish/validate/QA tooling; may be rough, must be deterministic and clock-blind where CI compares output | Application runtime code |
| `Models/**` | Trained artifacts + handshake JSON | Anything served publicly (explicitly 404'd in `backend/server.js`) |

### 4) Naming and Organization Rules

- **File naming — React/workspace TypeScript:** PascalCase for components
  (`frontend/src/components/AlertCard.tsx`, `apps/mobile/src/screens/alerts/AlertsScreen.tsx`);
  camelCase for modules and hooks (`useForecasts.ts`, `forecastView.ts`, `seoHead.ts`).
  Exceptions exist in shared TS packages (all lowercase: `contracts.ts`, `dataStates.ts`, `haptics.ts`,
  `savedPlaces.ts`).
- **File naming — backend/serverless JS:** camelCase (`forecastServe.js`, `chatService.js`) with
  two snake_case legacy holdouts (`backend/utils/ai_fallback_engine.js`, `backend/utils/gemini_grounding.js`).
- **File naming — scripts:** snake_case for pipeline builders/validators
  (`build_forecast_snapshot.mjs`, `validate_advisory_csv.mjs`) and kebab-case for the `check-*`
  gates (`check-bundle.mjs`, `check-public-paths.mjs`, `check-token-compliance.mjs`).
- **File naming — serverless:** Vercel dynamic segments are literal bracket files
  (`api/[endpoint].js`, `api/v1/[resource].js`, `api/v1/forecasts/[action].js`).
- **Directory organization:** layer-based on the server (`routes/`, `middleware/`, `services/`,
  `utils/`, `alerts/`, `security/`) and a feature-leaning layer split on the client
  (`pages/`, `components/<feature>/`, `hooks/`, `lib/`, `services/`, `design-system/`,
  `styles/`, `content/`, `locales/`, `types/`); monorepo packages are concern-based
  (`core`, `api`, `design-system`, `analytics`) and `apps/` is platform-based.
- **Tests:** root suites live in `__tests__/` (`*.test.js`, subfolders `alerts/`, `api/`, `mobile/`);
  component/unit tests sit next to the code in `frontend/src/**/__tests__/*.test.ts(x)`;
  package tests in `packages/*/__tests__/`; mobile component tests in `apps/mobile/__tests__/`;
  E2E in `e2e/*.spec.ts`; pipeline/workflow tests in `scripts/tests/*.py`.
- **Import aliasing:** `@/*` → `frontend/src/*` (tsconfig `paths`, mirrored in
  `frontend/vite.config.ts` `resolve.alias` and `jest.config.cjs` `moduleNameMapper`);
  `@hazardnet/core`, `@hazardnet/api`, `@hazardnet/design-system`, `@hazardnet/analytics` map to
  package sources (no build step for consumption — packages export `./src/*.ts` directly).
  Server code uses relative ESM imports with explicit `.js` extensions.
- **Barrel exports:** `packages/*/src/index.ts` re-export the package surface;
  `frontend/src/design-system/index.ts` and `frontend/src/components/brand/index.ts` are the
  frontend-side barrels. No project-wide barrel.
