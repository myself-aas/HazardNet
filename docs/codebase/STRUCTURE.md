### 2) Entry Points

- Main runtime entry: `backend/server.js` (`npm start` / `npm run dev`). Boot order: dotenv → env assertions (SEC-06) → helmet/CSP → requestId → CORS → static SPA serving → `/api` rate limiter → route mounts → `/metrics` → listen (`PORT` env, default 3000; dev convention 3001 via Vite proxy).
- Serverless entries (production, Vercel): `api/forecasts.js`, `api/ingest.js`, `api/metrics.js` — async `(req, res)` handlers.
- Frontend entry: `frontend/src/main.tsx` → `App.tsx` (route table with lazy pages) + service-worker registration (`frontend/public/serviceWorker.js`).
- Pipeline entry: `scripts/auto_forecast.py`, triggered daily by `.github/workflows/daily_forecast.yml` (GitHub runner — no Kaggle since 2026-09-17).
- How entry is selected: `package.json` scripts (`start`, `dev`, `build`); Vercel builds per `vercel.json` (`buildCommand: npm run build`, functions auto-detected from `api/`).
- Stale pointer: root `package.json` `"main": "index.js"` — **no `index.js` exists** (verified; scan "ENTRY POINTS: No common entry points found").

### 3) Module Boundaries

| Boundary | What belongs here | What must not be here |
|----------|-------------------|------------------------|
| `backend/routes/` | HTTP handlers only (request validation, response shaping) | Business/AI logic (delegate to `services/`, `utils/`) — e.g. `chat.js` delegates generation to `ai_fallback_engine.js` |
| `backend/middleware/` | Cross-cutting request concerns (rate limits, requestId, Supabase JWT attach, tensor validation) | Endpoint-specific business rules |
| `backend/services/`, `backend/utils/` | AI agents, fallback engine, caches, auth key verify, normalization | HTTP handling |
| `api/` | Thin Vercel handlers reusing `backend/` modules (import across the boundary: `api/forecasts.js` imports `../backend/forecastStore.js`, `../backend/services/advisoryAgent.js`) | Duplicated logic that should live in `backend/` |
| `frontend/src/pages/` + `components/` | UI; data via `hooks/` (`usePrediction` → `/api/predict`) and `services/` | Direct Firebase/Supabase config literals (ADR 0001: only `lib/config.ts` may hold a Firebase literal) |
| `frontend/src/lib/config.ts` | Single source of truth for client service config | A second Firebase config literal anywhere else (ADR 0001) |
| `rag_pipeline/` + `references/` | RAG index build & search over the reference corpus | HTTP concerns |
| `scripts/db/` | The only home for SQL migrations (duplicate `backend/migrations/` was removed, re-audit N-4) | Ad-hoc schema files elsewhere (`scripts/db/README.md`) |

### 4) Naming and Organization Rules

- Frontend files: **PascalCase** for components/pages (`LiveMapView.tsx`, `DistrictDetailPage.tsx`); **camelCase** with `use` prefix for hooks (`usePrediction.ts`, `useLeafletMap.ts`); camelCase for libs/services (`supabase.ts`, `firebase.ts`, `seoHead.ts`).
- Backend files: **camelCase** ESM modules (`rateLimit.js`, `apiKeyAuth.js`, `ai_fallback_engine.js`) — note snake_case appears in a few utility names (`ai_fallback_engine.js`).
- Tests: co-located `__tests__/` directories with `*.test.ts(x)` (frontend) / `*.test.js` (root backend suites); e2e as `e2e/*.spec.ts`.
- Directory organization: **layer-based** in `backend/` (routes/middleware/services/utils), **feature/domain-based** in `frontend/src/` (pages/components/hooks/lib/services/data/context/types/utils).
- Import aliasing: frontend uses the `@/*` → `frontend/src/*` path alias (tsconfig `paths` + matching Vite `resolve.alias`, added for shadcn-generated components — `frontend/vite.config.ts` comment). Backend uses relative imports only.
- SQL migrations: numbered `NNN_description.sql` (001–004) in `scripts/db/`.

## Extended Sections (Optional)

### Generated-vs-source boundaries

- `frontend/dist/` is the build output (copied to root `dist/` by `scripts/copy-dist.mjs` for Vercel's `outputDirectory`); never edit.
- `rag_pipeline/agent_knowledge_base.json` is **generated** from `references/` by `build_agent_knowledge_base.js` — freshness is CI-gated (`npm run check:rag-freshness`, `scripts/check-rag-freshness.mjs`).
- `Models/VERSION.json` is generated by `scripts/gen-model-version.mjs` with sha256 checksums of the committed model artifacts.
