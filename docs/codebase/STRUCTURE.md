### 2) Entry Points

- **Main runtime entry (self-hosted)**: `backend/server.js` — selected by `npm start` / `npm run dev` in `package.json`.
- **Production compute entry (Vercel)**: `api/**/*.js`, each exporting `default async function handler(req, res)`. Routing is file-system based; `vercel.json` declares `buildCommand`, `outputDirectory: "dist"`, and `includeFiles` for the chat functions.
- **Frontend entry**: `frontend/index.html` → `frontend/src/main.tsx` → `frontend/src/App.tsx` (~60 routes). Build chain is `frontend/package.json#scripts.build`: `build_model_performance.mjs` → `build_content_engine.mjs` → `vite build` → `frontend/scripts/prerender.mjs`.
- **Data pipeline entry**: `scripts/auto_forecast.py`, invoked by `.github/workflows/daily_forecast.yml` (cron `0 0 * * *`).
- **Secondary entry points**:
  - `scripts/build_forecast_snapshot.mjs`, `scripts/build_alert_snapshot.mjs`, `scripts/build_freshness_artifact.mjs`, `scripts/build_model_performance.mjs` — artifact builders (each supports `--check` for CI drift gates).
  - `scripts/hindcast/cli.py` — hindcast report CLI (`check --require-reports`).
  - `scripts/rehearse_alert_engine.mjs` — offline alert-engine rehearsal.
- **Entry selection mechanism**: `package.json#scripts`, `vercel.json` (`functions`, `buildCommand`), and the workflow `run:` steps. Note the codebase scan reports **"No common entry points found"** because the scanner's `ENTRY_CANDIDATES` list does not include `backend/server.js` — the entry point is real but non-canonical by name.

### 3) Module Boundaries

| Boundary | What belongs here | What must not be here |
|----------|-------------------|------------------------|
| `api/` | Method check, `guardRequest`, API-key verification, then delegate to a shared `backend/` module | Business logic duplicated from `backend/` (the shared-module pattern exists to prevent exactly this — see `backend/utils/forecastServe.js`, `backend/utils/chatService.js`) |
| `backend/routes/` | Express `Router` wiring, rate limiters, auth middleware, request/response shaping | Direct Firestore queries (must go through `backend/forecastStore.js`) |
| `backend/utils/` | Pure helpers + shared service implementations usable by both transports | Process/global state that a serverless invocation cannot reuse safely |
| `backend/forecastStore.js` / `backend/db.js` | The only data-access layer for forecasts | Route handlers importing `firebase/firestore` directly |
| `backend/alerts/` | Alert lifecycle: `assess` → `policy` → `store` → `notify` → `service` | Direct channel I/O outside `backend/alerts/channels/` |
| `frontend/src/lib/` | Pure client logic, config, SEO/i18n helpers | React components |
| `frontend/src/components/` | Presentational + container components | Direct `fetch` calls that bypass `frontend/src/hooks/` (partially violated — see CONCERNS) |
| `frontend/src/content/` | Build-time-generated + hand-authored site copy JSON | Runtime-mutated state |
| `scripts/` | Offline/build-time/CI tooling (Node `.mjs` and Python) | Anything the running server imports |
| `rag_pipeline/` | Retrieval index + search + skill router over `references/` | LLM provider calls (those live in `backend/utils/ai_fallback_engine.js`) |

### 4) Naming and Organization Rules

- **Directory organization**: mixed — mostly **layer-based** at the root (`backend/routes`, `backend/middleware`, `backend/utils`, `backend/alerts`), **feature/domain-based** one level down in the components (`frontend/src/components/map|blog|user|auth|status|alerts`), and **type-based** in `frontend/src/{pages,components,hooks,lib,context,types,utils}`.
- **File naming**, verified against 10+ files per group:
  - `backend/**/*.js` → **camelCase** (`forecastStore.js`, `apiKeyAuth.js`, `predictFromStore.js`).
  - `frontend/src/**/*.tsx` components → **PascalCase** (`LiveMapView.tsx`, `DistrictDetailPage.tsx`).
  - `frontend/src/lib/**/*.ts`, `hooks`, `utils` → **camelCase** (`seoHead.ts`, `useLeafletMap.ts`).
  - `scripts/**/*.mjs` → **inconsistent**: snake_case (`build_content_engine.mjs`, `check-rag-freshness.mjs` mixes) alongside kebab-case (`check-bundle.mjs`, `audit_frontend_design.mjs`).
  - `scripts/**/*.py` and `scripts/tests/` → **snake_case** (`auto_forecast.py`, `test_model_claims.py`).
- **Import aliasing**: `@/*` → `frontend/src/*`, declared in **two** places that must stay in sync — `frontend/tsconfig.json#paths` and `frontend/vite.config.ts#resolve.alias` (the config comment notes Vite does not read tsconfig `paths`). Applied consistently for shadcn-generated UI components.
- **Workspace layout**: root manifest owns backend + tooling; `frontend/` is the only workspace member.
