### 4) Naming and Organization Rules

- **Directories: kebab-case or snake_case, never camelCase.** `packages/design-system`,
  `data/historical-sources`, `.github/workflow-templates`; pipeline scripts use snake_case
  (`build_climatic_hazards_summary.mjs`) while gate scripts use kebab-case (`check-bundle.mjs`).
  Both patterns are live; the split is by family (pipeline vs. gate).
- **React components: PascalCase `.tsx`** — measured 129 of 141 `.tsx` files under
  `frontend/src/components` (the 12 exceptions are non-component modules and lazy wrappers
  such as `3d-globe.tsx`, `motion-navigation-menu.tsx`, `primitives.tsx`).
- **Non-component TS modules: camelCase** — `forecastServe.js`, `chatService.js`,
  `hazardPalette.ts`, `oauthProviders.ts`.
- **Tests: `*.test.{js,ts,tsx}`**, in `__tests__/` — either at a workspace root
  (`packages/core/__tests__/`, `__tests__/alerts/`) or **co-located inside the directory under
  test** (`frontend/src/lib/__tests__/`, `frontend/src/pages/__tests__/`). Both are collected by
  the one root Jest project.
- **E2E: `*.spec.ts`** in `e2e/` — a deliberate split from `*.test.*` so Jest's
  `testPathIgnorePatterns` can exclude `/e2e/` and Playwright's `testMatch` can include it.
- **Mobile screens are grouped by feature folder**: `apps/mobile/src/screens/{today,advisories,
  alerts,articles,map,more,onboarding,report,saved,settings}/…` — feature-first, unlike the
  web app's layer-first `pages/` + `components/`.
- **Import aliasing**: `@/*` → `frontend/src/*` (web) and `apps/mobile/src/*` (mobile);
  `@hazardnet/{core,api,design-system,analytics}` resolve to **package source**, declared three
  times and kept in sync by hand — `frontend/tsconfig.json` `paths`, root `jest.config.cjs`
  `moduleNameMapper`, `apps/mobile/jest.config.cjs` `moduleNameMapper`.
- **Generated files are named as such**: `infinity.generated.ts`, `generated-routes.json`,
  `icons.ts` (generated from a registry), `AutolinkedNativeModules.g.*` (MSBuild).
- **Gate scripts are `check-*.mjs`, builders are `build_*.mjs`, fetchers are `fetch_*.mjs`.**

### Workspace-level structure

Root `package.json` owns the runtime deps for **both** server runtimes and the shared dev
toolchain; `frontend/` owns the browser deps; the four `packages/*` own almost nothing
(`core` → `zod`, `api` → `core`+`zod`, `analytics` → `core`, `design-system` → nothing).
`apps/mobile` and `apps/windows` depend on `@hazardnet/core` and `@hazardnet/design-system`
via `"*"`, resolved from source by their Jest/Vite/Metro alias maps rather than built —
`packages/design-system` is the only workspace with a `build` script.

The consequence, recorded in `docs/audits/2026-10-02-mobile-windows-support-audit.md` §4:
**the release path is not the developer path.** `app-releases.yml` copies `expo`,
`react-native` and `react-native-windows` into app-local `node_modules` because Metro/MSBuild
expect them locally while the workspace hoists them to the root. At HEAD, `app-releases.yml`
also triggers on **push to `main`** (automatic Android APK releases — the HEAD commit's own
subject: *"build: configure automatic Android APK releases on main"*), and a dedicated PR
compile workflow exists for Windows (`.github/workflows/windows-compile.yml`, owner decision
#10 of 2026-10-10).
